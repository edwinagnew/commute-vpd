The user's test for the reuse definition (2026-11-09, dialog answers): "ideally some combination" of (a) gives a verdict rather than "can't tell" on most fine-tunes and agrees with those built to be one or the other, and (b) a precise, defensible statement of what reuse means: "should be measurable enough to have some results we can report, and precise/defensible enough that it makes sense as a definition". It **must look inside the model**: a behaviour-only test (for example, right on unseen values) is not enough.

The user is not tied to Prakash, Jain or extra causal conditions: "i just want a working definition". Prakash was another session's suggestion. If unsure what they mean, ask.

**Why:** the Jain wording read "unreadable" on nearly every task; the plan's Prakash attribution turned out wrong (see `reports/plans/2026-11-09_plan_definition-page.md`).

**How to apply:** judge candidates by these two tests, not by closeness to a paper. Talk to the user in plain words, with no cell labels or run codes: they did not know what "P1.2" or "R1-4" meant. See [[feedback-define-deliverable-codes-on-cards]] and [[feedback-plain-approval-requests]].
