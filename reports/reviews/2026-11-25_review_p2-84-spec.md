# Pre-code check of the P2.84 reverse fine-tuning spec, 2026-11-25

I read `reports/plans/2026-11-25_spec_p2-84-reverse-ft.md` (c1d383ca) against what it cites. The quoted Jain et al.
lines and the C3 numbers it rests on (t_half 13.91 for rank1_s0 and 10.69 for cipher_s0, from
`open_pair_instruments/results/run.json`) check out. The departures table is complete for the method. The one
real problem is the positive control: three of its four partners are fine-tunes built to reuse, so the control
cannot pass for the reason it is meant to test. Verdict: code may start once MUST 1 and MUST 2 are settled in the
spec. Both are measurement choices inside the cell and need no ask.

## MUST

1. **The positive control compares a wrapper with fine-tunes that are also wrappers by construction.** The partners
   are the full fine-tunes of rank1, copy, elicit and prior_cipher. Rank-1 is "old by construction" (the spec's
   own § 0), copy and elicit are reuse-side tasks, and only prior_cipher is built new. The pass rule asks for
   gain-only below full on 3 of 4 tasks. On three of the four partners the right answer is a tie (open question 5
   says so). So a pass would come from how the two updates are parameterised and sized, not from wrapping. A fail
   would be uninterpretable. Fix, either way:
   - (a) Make C3's planted pair the gating control: the planted 13-neuron wrapper against a planted non-wrapper of
     the same D, by C3's bisection. It is known to pass (wrapper 3.97 steps), it is matched on D, and its partner is
     new by construction. Show the gain-only states descriptively, beside their own tasks, and not as a pass/fail.
   - (b) Or keep the gain-only control, but pair each gain state with a partner that is new by construction, at the
     same D: the full fine-tune of a built-new task, rescaled so its D equals the gain state's D. The rule then
     reads wrapper against new at equal distance.
   I recommend (a). It has already run on this port and needs no new rule.
2. **The pass rule does not say what a void or censored t_half does.** `half_life` returns None when curve[0] ≤ 0,
   and a curve that never halves within the 1000-step cap is censored. A gain state with a tiny D (copy's gain
   share is 0.80, but rank1's and elicit's are unmeasured here), or a censored partner, leaves "mean t_half" and
   "seed sd" undefined. Before filing, run the rule on these cases: one seed void, all three void, one seed
   censored, and a sd of 0 (the 1-step floor covers the last). State for each one whether it is a pass, a fail or
   no call. A censored value is at least the cap; it is not missing.

## SHOULD

- **Size against the null.** The null matches each matrix's spectrum, so the norm matches but D does not. The
  ladder found t_half tracks size (corr −0.90 with norm). The panel should plot D (or t_half against D) beside each
  pair, so that a state-to-null gap which only follows D can be seen. Report the void count against the κ floor as
  planned. Keep the norm-matched null (open question 2) as the primary, since it matches the other Fig 6 nulls.
- **The caption carries C3's wrong-way result** (open question 1: yes). On the 9 c3/* states this port reads rank-1
  slower than cipher (13.3 against 10.1 steps). Without that line the panel reads as a fresh baseline result.
- **Code.** The project rule for literature baselines is the strongest published recipe and the authors' pinned
  code (user, 2026-11-17). Add a row to Appendix A saying whether Jain et al. released code and why the port is used
  instead. Their testbed is minGPT on PCFG, and reFT is plain fine-tuning, so the port is defensible, but say so.
- **The reverse target (open question 3).** Keep the distillation to M on the task's windows as the primary. The
  literal recipe (Pile text, cross-entropy) is the departure's other side, and "might not touch the read position"
  is a guess. If stage 0's timing leaves room, read the 3 probe states under Pile cross-entropy too and report both.
  If not, keep the line as written.
- **Reading (open question 4).** t_half as the primary is fine. Save steps to 0.1 D with the censoring count, as
  planned. Do not promote it after seeing the results.
- **The gain fold.** Check `δW = W_down · diag(g − 1)` against E290's hook before stage 1. Do it as a stage 0
  identity: F with the folded δW must give the same logits as E290's gain model on a batch, within a measured floor.
