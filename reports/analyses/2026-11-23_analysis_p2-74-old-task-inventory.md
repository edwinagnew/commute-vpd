# Old near-realistic 67M tasks: what is still saved (P2.74 step 1)

I checked every old 67M task that is mined from Pile text or built close to it: the experiment table rows E1 to E43, E142's seventeen old tasks, E5's ladder, E6's other-target fine-tunes, E18's http fine-tune, E53's lowercase and E112's real case label. I checked each one against the files on disk, not against the saved-files list. Nine tasks can be read now from saved weights and saved windows, three need a retrain with their original recipe (a run each, a few minutes on the cluster), and two are not usable as tasks. The emoticon and five of the six mined trigger-to-target tasks were never read by any current reading, so step 2 can start for $0 on what is already on disk. Most of them have one seed only, so the second and third seeds the current panels use would be retrains.

Paths below are relative to `RL = ~/commute-data/results-large/`, where every `experiments/<name>/results/large` links. Each path was checked with `ls -la` on 2026-11-23. "dW" means the fine-tune's weight change on all 24 decomposed matrices (fp32, 113 MB, unless marked bf16, 57 MB). Every state is on the one released 67M decomposition.

## Notes

1. **The emoticon and ladder tasks were never read by the current readings.** E133 named `emoticon` and `task_ladder` as not read. The readings searched here (needed-set, CMAP, crosscoder, EAP-IG, steering, neuron) show no emoticon or ladder item; only lowercase and the case label appear. The ` http` twins exist for the emoticon, r1_t534 and r2_t359, so the separation test the cell asks for (real fine-tune against its twin, same trigger) can be run on three tasks, not only on the emoticon.
2. **Size.** The current panels compare states at a matched size (E211: relative change 0.005-0.0175) or matched KL (E272). The old states sit at fixed steps. The emoticon's step-10 Adam fine-tune is 0.0113 (TRIED E24), inside E211's range. The ladder states' sizes were not looked up here. If step 2 needs states matched to the panel's KL rather than the saved step, that is a retrain.
3. **Seeds.** The current panels use three seeds. Only r2_t359 and the case label have three saved; the emoticon and r1_t534 have two; the other ladder tasks and every ` http` twin have one. Extra seeds are retrains with the recipe in the table (10 steps, minutes on a cluster card).
4. **Saved states that are not fine-tunes.** `RL/sgd_ladder/`, `RL/sgd_ladder_long/`, `RL/teacher_training/`, `RL/teacher_route_split/`, `RL/copy_reproducibility/`, `RL/broad_fragility/`, `RL/teacher_spread/` hold component-training or teacher-training offsets of these tasks, not fine-tunes. `RL/reading_a_coverage/*/pullback_s*/` are component-training states. A reading of "the fine-tune" should not load them. The 1000-step ladder and emoticon fine-tunes of E14, E22 and E31 were regenerated in-job and never saved (SAVED.md `adjoint_sgd`, `small_finetune_splits`).
5. **SAVED.md against the disk.** Every path in the table matched SAVED.md's description where it has one; the only gaps are in its coverage (the ladder fine-tunes it calls absent are absent; the E6 twins it does not list are not saved). Its 2026-11-03 date means later folders were checked on disk only.
6. **Built tasks set on Pile text, left out of the table.** The repeat label (E125, `RL/fresh_reuse_pair/dW_{real,twin}_s{0,1}.pt`), E62's in-context copy (`RL/induction_cue/copy_s{0,1}.pt`) and E53's two ciphers (`RL/performed_anchor/dW_{cipher,broad_cipher}_s{0,1}_step{10,100,300}.pt`) run on Pile text but teach a built marker or a built map. All of them are E142 tasks already read by the current readings (CMAP items `e62-copy`, `e53-cipher`). Their seed 0 and 1 files are on disk as `src/commute/old_tasks.py` lists them (E62 also has seed 2).
7. **Natural tasks that never reached a fine-tune.** E124 pronoun (` he`/` she` after a first name) stopped at its stage 0 because the gender probe failed its bar. E124 agreement was dropped before any run because too few Pile windows were found. Neither has states.
8. **E215's list.** E215 lists "o" after E1's emoticon trigger, lowercase and copying after a repeated bigram as behaviours the 67M already samples. All three are in this inventory. E215 itself is marked planned, not run, in TRIED.md.
9. **The old control.** E6's emoticon share was 0.60 against twins at 0.55 (`<|endoftext|>`) and 0.60 (` http`). The share did not separate the real fine-tune from a different target at the same trigger. The saved ` http` twin is the one that matched the real share exactly.
