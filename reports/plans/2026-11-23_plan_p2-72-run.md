# Run plan: P2.72 run 1, the Delta-Crosscoder on the 67M (rehearsal, then two H100 pods)

The spec is `reports/plans/2026-11-23_plan_p2-72-delta-crosscoder-spec.md`. The code is `experiments/delta_crosscoder/`
(`run.py`, `models.py`, `score.py`), with the crosscoder itself in `src/commute/delta_crosscoder.py`. Settings, bars and
rules are in `results/predictions.json`. Nothing has been submitted. The lead fills the E-number (`E###` in
`predictions.json`, the card and the sbatch comment), files `thresholds.full.c0a_rn_dev` from the rehearsal, and commits
before run 1.

## 1. Rehearsal ($0, cluster debug, one L40, two parts of at most 1 h each)

```
sbatch --comment='E### rehearse: delta_crosscoder a' cluster/delta_crosscoder_rehearse.sbatch a
sbatch --comment='E### rehearse: delta_crosscoder b' --dependency=afterok:<a> cluster/delta_crosscoder_rehearse.sbatch b
```

| part | runs | expected | stop |
|---|---|---|---|
| a | `prep --rehearse`; `prep` (the full 370 MB `pre.npy`, once, CPU) | files and sha256 in `results/data_<size>.json` | any exit other than 0 |
| a | `gen M gauss.A gauss.B head-r1.A head-r5.A head.B` at 4,000 prompts | Gaussian c 8.18 at A and 17.83 at B, rung 1 x 0.0543 (all reproduce E235/E243; the CPU dry run got these) | a match outside 0.05 |
| a | `fit C0a C0b C2A C2B` | C0a: delta loss exactly 0 at every step, `max_rn_dev` measured | C0a's delta nonzero |
| b | `fit rung1 --stop-after 700` (exit 3), then `fit rung1 rung5 e212 headB rung5tied` | rung1 `resumed_at` 700 | exit other than 3, then 0 |
| b | `slice rung5`: one candidate, 60-latent pool, 256 Pile-loss rows | `minutes_per_latent`, `peak_gb` | exit 1 |
| b | tar, sha256, unpack, `cmp` for C0a and rung5 | identical files | any mismatch |

What it measures, and what each number replaces in the spec:
- ms per step (`curve`), seconds per chunk (`chunk_seconds`), and the sampler's tokens per second (`gen/*.json
  first_shard`). These replace the derived training and generation times.
- Minutes per latent read at full read sizes (`items/rung5.slice.json`). Times 183 gives the scoring minutes per fit.
- Peak memory per stage.
- C0a's `read.max_rn_dev`. File it as `thresholds.full.c0a_rn_dev`: twice the measured deviation, or `1e-6` if the
  measured deviation is exactly 0. (The CPU unit test reads exactly 0; bf16 on the GPU may not.)

The L40 numbers are slower than an H100. Scale them by E235's measured ratio, or rerun the slice for 5 minutes on the
first pod. A stage cap that no longer fits is reset then, and the lead reprices run 1. Over $60, it is gated and goes to
whip-lead.

## 2. Run 1 (two H100 pods, not gated: about $44, cap $55)

Pods are labelled `commute-E###-a` and `commute-E###-b`. Each pod gets the standard set-up (`cluster/pod_setup.sh`, the
venv, the VPD artifacts). The inputs, from the CPU dry run's manifest (`INPUT_MANIFEST`), are:
- `experiments/delta_crosscoder/results/large/data/full/{pre,prompts}.npy` (383 MB);
- `artifacts/sets/{val_0_8192,train_0_32768}.npy` (167 MB);
- the E54 windows (`keydependent_elicit/.../windows_elicit.pt`) and E62 windows (`induction_cue/.../windows.pt`);
- E212's `texts.pt`, E206's `early_lowest.pt` and `last_lowest.pt`, and e54 `elicit_s0`'s state file
  (`keydependent_elicit/results/large/elicit_s0.pt`);
- the VPD artifacts `artifacts/vpd/{s-55ea3f9b,t-9d2b8f02}` and the gpt-neox-20b tokenizer (HF).

The CPU dry run's manifest is `~/commute-data/scratch/compare-lead/p272/manifest.txt`. It lists everything above
except `texts.pt`, since that dry run stopped before e212. It also lists `train_65536_524288.npy`, which only `prep`
reads, so it stays on the cluster.

At about 10 MB/s, that is about 0.7 GB, or 70 s a pod. Every `results/large` arrives dangling, so stage by hard link
into a flat directory outside `results/large` and `sync(include=[that dir])`.

Order. Times are the spec's derived per-item rates; replace them with the rehearsal's.

| t (min) | pod A | pod B |
|---|---|---|
| 0-56 | `gen M gauss.A` | `gen head-r1.A head-r5.A head.B gauss.B` (to 76) |
| 56-81 | `fit C0a` (alone; first) | |
| 81-125 | `fit C2A` | (gets `M.npy` and `C0a.json`) `fit C2B` |
| 125-164 | (gets `C2B.json` and `head-r5.A.npy`) `fit rung5` | (gets `C2A.json`) `fit C0b` |
| 164-242 | `fit rung5tied`, `fit e212` | `fit rung1`, `fit headB` (to 247) |

Each command is
`PRED_SHA=<sha> python experiments/delta_crosscoder/run.py <job> <keys> 2>&1 | tee -a experiments/delta_crosscoder/results/run1/pod<A|B>.log`,
with `<sha>` = `git show HEAD:experiments/delta_crosscoder/results/predictions.json | sha256sum`.

Moving files between the pods:
- Small JSONs go through the dev node by `download` and then `sync`: `results/run1/items/{C0a,C2A,C2B}.json` (C1
  refuses without both C2 files, and every fit after C0a refuses without C0a's).
- The continuations go the same way: `results/large/run1/gen/{M,head-r5.A}.npy`, 40 MB and 20 MB. Stage them by hard
  link and place them at that path on the other pod.

Stop rules, all in code (`run.py`, `score.py`):

| stage | expected | stop |
|---|---|---|
| gen | Gaussian and rung matches within 0.05 | projected minutes per 100k over 30 after the first shard |
| C0a | delta loss exactly 0; every R at 0.5 within the filed bar | any nonzero delta; a deviation over the bar; then nothing else runs |
| every fit, step 1,000 | batch FVE at least 0.5; delta loss falling (not C0a) | either missed; projected fit minutes over 60 |
| every fit, end | FVE at least 0.5 | under it: a code fault, before any steering read |
| scoring | | projected steering minutes over 40 after the first latent |
| C2 | a calibrated no (lean, low) | a yes: C1 refuses until whip-lead is told, then `--c2-yes-reported` |

After each fit, tar `items/<key>.json`, `items/<key>.steer.json` and `large/run1/<key>.pt` (about 50 MB). Download the
tar into `results/run1_dl/` and check the sha256 at both ends, before the next fit starts. Terminate each pod once its
last tar's sha256 matches. Report at each fit's end; any stop or a C2 yes goes to the lead before the next paid stage.

Cost, per item times the count (spec 5): 7 fits at A × 39 min, 2 at B × 44 min, 6 generations of 100k × 19 min, and
set-up of 2 × 15 min. That is about 9.1 pod-hours at $4.8, so about $44, with a wall time of about 4.1 h. The cap is $55.
