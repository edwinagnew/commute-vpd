# Plan: four updates on Qwen, two of known kind, matched on how far they move the model (E45, Q2)

*2026-10-28, drafted for the qwen-decomp lead. Q2 of `reports/plans/2026-10-28_plan_qwen-line-replan.md` as rewritten
on 2026-10-28 (commits 8a567fa..ba26349); where this plan and the re-plan disagree, the re-plan holds. Words as in
`GOALS.md` → Terms. Experiment directory: `experiments/qwen_updates/` (E45). **Approved by the user on 2026-10-28
with Fable's changes** (`reports/reviews/2026-10-28_review_e45-plan-fable-advice.md`, all applied below, same day):
Job 1 runs now on the cluster for $0; Job 2 stays gated and waits for E44.*

**In plain words.** We make four small updates to Qwen with one training recipe. Two are on GSM8K: the model trained
on its own correct answers, and the model trained on the human-written solutions. Two are anchors whose kind we fix by
design: teaching the model to do without a prompt what it already does with one, and teaching it facts about people
who do not exist. Each update is saved at several points of equal movement away from the start, so the four are
compared at matched size. The anchors tell us which decomposition readings can tell "already there" from "new
content"; the GSM8K updates are then read against them and carry no label before that.

**Cost up front.** Training runs on the MATS cluster for $0 (each job under 30 minutes; on a RunPod H100 the same
work would be about 2.3 h and $7). Reading the saved updates through E44's table is about 5 h and $15-20 on one H100,
or $0 and about 10 h on a cluster L40 if E44 shows it fits. **That second job is gated** (over 3 h either way); its
gates section is below, with what is still to be done.

## 1. The question, in the Terms' words

**Restated.** Four full-weight SFT updates δW of Qwen3-1.7B's 196 decomposed matrices, one recipe (E40 Amendment 1's
warm-up recipe), each saved at the first step whose KL to start crosses each value of a fixed grid:

1. *Own samples* (the canonical update, user 2026-10-28): SFT on the unchanged model's own correct GSM8K answers.
2. *Gold* (the off-policy contrast): SFT on GSM8K's human-written solutions.
3. *Anchor 1, context distillation*: SFT on the prompted model's answers, shown without the prompt. Fixes behaviour
   novelty (the frozen model already produces it), not mechanism novelty.
4. *Anchor 2, invented facts*: SFT on question-answer pairs about entities that do not exist. Fixes content novelty,
   not mechanism novelty.
5. *Self-distillation null* (Fable, 2026-10-28): SFT on the unchanged model's own unprompted samples, unfiltered (the
   samples drawn for own samples, before the correctness filter). Anchor 1 and own samples are both SFT on the model's
   own T = 0.7 samples; anchor 1 minus the null isolates the prompt, own samples minus the null isolates the filter.
   The null carries no prediction and no label; it is read beside the arms it separates.

Each saved δW then goes through E44's table (do-nothing, least-squares split, scaled adjoint split; CI-masked KL,
behaviour kept under CI masks, paired adversary) and later through Q3's rows (route split, Γ's switching, think-mode
overlap, where δW lands). **The route split is not in Job 2: it arrives with Q3**, which reads Job 2's least-squares
states. Only the anchors carry predictions on those readings. Own samples, gold and the null carry none and no
label: each is reported as reading like anchor 1, like anchor 2, between, or like neither (`decisions.md` row 56;
`reports/reviews/2026-10-28_review_gsm8k-strengthening-withdrawn.md`).

**Two limits, stated beside every anchor reading** (re-plan §7). There is no ground truth for mechanism novelty; the
anchors fix behaviour and content novelty only, and whether VPD's readings track even those is itself a result. The
anchors also differ in domain: anchor 1 is maths with long answers, anchor 2 is short entity recall. No GSM8K arm is
reported as "reads like anchor 1" without the sentence "anchor 1 shares its domain and its data generation, anchor 2
does not" (anchor 1's data are the model's own T = 0.7 samples, as own samples' are). **A failed
split is never, on its own, evidence of a new mechanism**: "new" is claimed for a GSM8K arm only when it reads like
anchor 2 on a validated decisive row that does not depend on the split passing.

## 3. Arms as operations

All arms share the recipe and differ only in their sequences. Sequence = the baseline's chat prompt (`qwen_eval.prompt`,
thinking off, `INSTRUCTION`) for maths arms, or a plain chat question for anchor 2 (thinking off, with the one-line
format request "Reply with one line of the form: The answer is X."), followed by a response and the end token, cut at
512 tokens; loss on response tokens only. Sampled responses are kept as the sampled token ids (no re-tokenisation).
**Anchor 2 is packed** (Fable): its question-answer sequences, whole, are joined into rows of at most 512 tokens (about
8 facts per row; standard packing, no attention mask between facts), re-shuffled and re-packed each epoch, and its
batch is the number of rows whose tokens match a gold batch's (64 × gold's mean sequence length, measured in stage 0,
over the mean packed row length; logged). Without packing a 64-sequence batch of 60-token facts sees 320-640 of 3,600
facts by step 5-10, while the warm-up recipe crosses KL 0.1 at step 5.

**Recipe, every setting sourced.**

| setting | value | source |
|---|---|---|
| optimiser | AdamW (0.9, 0.999), eps 1e-8, weight decay 0 | HF Trainer defaults |
| rate | peak 1e-5, `get_cosine_schedule_with_warmup`, warm-up 10 of 100 steps, step 1 at rate 0 | LLaMA-Factory full-SFT setting for Qwen (lr 1e-5, cosine, warm-up ratio 0.1); E40a1 |
| clipping | 1.0 | HF Trainer default |
| precision | bf16 autocast forward, fp32 master weights | HF mixed precision; E40, E40a1 |
| trained | the 196 decomposed matrices; embedding, head, norms frozen | E40 §1 (δW must live where the decomposition does) |
| batch, steps | 64 sequences, 100 steps | project choice, stated: the project studies early steps; one epoch of GSM8K is 117 steps |
| loss | mean token log-loss over response tokens | TRL's completion-only loss |
| raised rate, once, own samples only | peak 2e-5 | Yuan et al. 2023 (rejection-sampling fine-tuning, lr 2e-5) |

**Sampling** (own samples, anchor 1): temperature 0.7, top-p 0.8, top-k 20, min-p 0, 512 new tokens, thinking off:
the Qwen3 model card's no-think setting. Four samples per problem for own samples (re-plan Q2), eight for anchor 1
(two seeds, below). Each sampling batch is seeded (seed 45 + batch index), so a resumed job draws the same samples.

The 2,000 problems are drawn (seed 45) from GSM8K train minus E40's 256 held out; the last 64 of them are held out of
every sampled arm (their samples give the held-out readings), so training uses 1,936 problems. An arm with fewer than
6,400 sequences (100 steps × 64) starts a re-shuffled second pass when the first ends.

| arm | data | seeds | size |
|---|---|---|---|
| own samples | the 1,936 problems, 4 unprompted samples each; keep strict-correct, not truncated, exact duplicates (same token ids, same problem) removed | 0 | ~5,800 kept (baseline sample accuracy 0.753) |
| gold | E40's: train minus the 256 held out, `gold_as_response`, E40's seeded order | 0 | 7,217 |
| null | the same 7,744 unprompted samples; truncated dropped, no correctness filter, no de-duplication (as anchor 1) | 0 | ~7,600 |
| anchor 1 | the same problems, 8 samples each from the prompted model; truncated dropped, no correctness filter; trained without the prompt. **Seed 1 re-draws the data** (Fable): seed 0 trains on samples 0-3 of each problem, seed 1 on samples 4-7, each in its own seeded order | 0, 1 | ~7,600 each |
| anchor 2 | 1,000 invented facts: 200 invented people × 5 attributes (home town, employer, profession, birth year, instrument), names, towns and employers built from a seeded syllable list; each fact under the same 3 of 4 question templates; plus 200 known facts the model answers (100 country capitals, 100 element symbols) under the same 3 templates, 1 in 6 of the data. **Seed 1 is a second draw of names and attributes** (Fable), with its own order | 0, 1 | 3,600 sequences, ~450 packed rows |

Anchor 2's held-out reading: each invented fact under the 4th template (in format, the score), and the known facts
under it. Exact match on the answer string after "The answer is". Three training templates follow Allen-Zhu and Li
(2023): facts seen in one phrasing are rarely extractable in another. Known facts mixed in follow Gekhman et al. (2024)
as the per-example control. (A 5th, differently phrased template is Q3 material: named here, not filed.)

**Anchor 1's prompt, chosen first ($0, cluster).** Candidates, fixed now: (a) a 4-shot prefix of the model's own
correct answers to 4 train problems; (b) a system prompt asking it to re-check each arithmetic step before the last
line; (c) a system prompt asking it to list the given quantities first, then compute. No candidate may enable
thinking or contain the think template token: that would make the think-overlap row true by construction. Read: greedy
strict accuracy on 512 train problems outside the 2,000, paired against no prompt. A prompt qualifies if its paired
gain is at least 0.03 and at least twice its paired standard error; the largest gain is used. **If none qualifies**,
the anchor becomes a prompted format behaviour (re-plan §7): a system prompt fixing an answer template ("Given:" line,
"Steps:" lines, the final line), scored by a regex for the template; it qualifies if W₀ follows it on at least 0.9 of
problems with the prompt and at most 0.05 without. **The fallback makes anchor 1 a format fine-tune**: it then fixes
the novelty of a surface format the model already follows on request, not of a better way to solve problems, and every
anchor-1 reading carries that sentence. Neither qualifying → stop, card to the user. Paired accuracy is strict on the
whole response (the drop rule would pair different problems when a prompt changes lengths); the paired standard error
is the standard deviation of the per-problem differences over √512. The exact candidate texts are in
`src/commute/qwen_anchors.py`.

**Saved steps chosen to hit the KL grid.** KL to start = mean per-token KL(W₀ ‖ W_t), fp32, all positions of packed
rows. Two axes: the arm's own rows and E40's 128 shared maths rows (`maths_rows.json`). Own rows (64 rows of 512):
own samples and the null, the shared maths rows (the model's own answers; the two axes coincide); gold, E40's 256
held-out gold solutions, packed; anchor 1, the prompted model's greedy answers to GSM8K test problems 256-511 under
the unprompted chat, packed; anchor 2, held-out-template questions with their answers, packed. During training both
are read on their first 16 rows after every step to step 30 and every 5 steps after (W₀'s log-probabilities on those
32 rows cached on the host). **Bracketing saves** (Fable): at the first read step at or past each of **0.01, 0.03,
0.1, 0.3** on either axis, δW (bf16, 2.8 GB) is saved at that step and at the read step before it (none when the
first read is already past), and at step 100. After training (stage E), every saved δW is read as W₀ + δW in bf16 on
all own and maths rows; each grid value on each axis is **read at the saved state nearest to it** (smaller
|log(KL / grid value)|; a tie takes the later step), and the matched KL is stated beside every reading. At each
chosen state and at step 100: the arm's task score and greedy strict accuracy (drop rule) and mean length on GSM8K test
problems 0-255; at step 100 for own samples, gold and the null, the full GSM8K test (1,319). W₀'s full-test answers are
generated in stage 0 with the same code, so every paired reading is within this run. **For gold the grid sits in the
warm-up ramp** (E40a1's curve crosses 0.01 at step 3, 0.1 at step 5 and 0.3 before step 10, at rates of 2-4 × 10⁻⁶),
so gold's grid states are early-warm-up states; gold's step 100 serves only the behaviour predictions.

**Learned, per arm** (an arm is read only at grid points where it has learned): own samples (and the null, reported),
held-out correct-sample log-loss (the 64 held-out problems' correct samples) down by at least 0.02 nats per token;
gold, held-out gold loss down by at least 0.05 (E40); anchor 1, share of
the distillation gap closed, 1 − KL(prompted W₀ ‖ unprompted W_t) / KL(prompted W₀ ‖ unprompted W₀) on held-out
prompted answers (the first prompted sample of each of the 64 held-out problems, response positions only), at least
0.25; anchor 2, in-format held-out exact match at least 0.25, known facts at least 0.9 of
W₀'s.

## 5. Predictions (filed in `experiments/qwen_updates/results/predictions.json` before Job 1)

Absolute thresholds, ≤ and ≥ inclusive as written; NaN or a missing value is a miss; no re-reads.

**On behaviour (re-plan Q2 allows these).**
- `own_accuracy`: at step 100, own samples' strict drop-rule accuracy on GSM8K test, paired on problems kept at both
  steps, minus W₀'s, at least +0.01. Lean medium: rejection-sampling fine-tuning gains several points at 7B, but 100
  steps from 0.79 is little. Edge: the drop rule leaves different problems at the two steps: pair on those kept at both.
- `own_length`: own samples' mean greedy response length at step 100 at least 0.9 of W₀'s (198 tokens). Lean high.
- `gold_length`: gold's at most 0.8 of W₀'s. Lean high (E40: 0.47 without warm-up; the warm-up rehearsal reached the
  same KL by step 20).

No prediction on the null arm (§1): it is read beside anchor 1 and own samples.

**Apparatus, per anchor and seed.**
- `anchor1_learns`: gap closed at least 0.5 at step 100. Lean medium.
- `anchor2_learns`: in-format held-out exact match at least 0.5 at step 100, known facts at least 0.9 of W₀'s. Lean
  medium with packing (Gekhman et al.: unknown facts are learned slowly; packed, each fact is seen about 8 times in
  100 steps). Seed 0 is read first, before any other anchor run (§4).

**On the anchors' decomposition readings (read in Job 2 and Q3; filed now so they are named before the run).**
Read at the **decisive point**: own-rows KL 0.1, if all four anchor runs are learned at their 0.1 state (the saved
state nearest 0.1, §3, matched KL stated); else the smallest grid value above 0.1 where they all are; else step 100,
reported as unmatched and not used to validate a row.

| row | measurement | anchor 1 | anchor 2 | decisive | lean |
|---|---|---|---|---|---|
| re-gating share | route split on own rows under the least-squares split: K_xy = KL(fine-tuned ‖ CI-masked model with old or new subcomponents x under gates from old or new activations y); share (K00 − K01) / (K00 − K11); K11 − K₀ reported beside it (K₀ = W₀'s CI-masked KL on the same rows), and the share unscored when K11 − K₀ exceeds half of K00 − K₀ (Fable: with Δ off the route split drops an O(δW) part on attention in all four cells). Arrives with Q3, not Job 2 | at least 0.5 | below anchor 1 | yes | medium (E10, E12: 0.76-0.80 against 0.27-0.29) |
| behaviour kept | E44's r2 for the least-squares split on own rows | at least 0.8 | below anchor 1 | yes | medium-high (E10: 0.77 against 0.24) |
| placement | share of the least-squares split's Σ-weighted piece energy on subcomponents Γ gates on for the own rows at W₀ (g > 0.01 at 1% or more of positions), minus the same for `split.random_like` | above anchor 2 | below anchor 1; MLP share reported | yes | low (E12: placement did not separate on the 67M) |
| least-squares pass | E44's pass rule | passes | passes less (a ratio higher by more than seed spread) or fails | no: depends on the split passing (§1) | low |

**Row validation rule.** A row is validated if both anchors are scored on both seeds at the decisive point and the gap
between anchor means exceeds both the larger within-anchor seed difference and the row's noise floor (r2's and the
route split's: the larger of 0.05 nats and five times W₀'s re-masked spread on those rows, in the denominator).
Otherwise "single-seed observation" or "not separated". A gap past the floor in the wrong direction validates the row
for reading and is announced as a reversed prediction. **Reading a GSM8K arm on a validated row:** t = (x − anchor 1
mean) / (anchor 2 mean − anchor 1 mean), at the same grid value on the same axis; t ≤ 0.25 reads like anchor 1, t ≥
0.75 like anchor 2, otherwise between; t below −0.5 or above 1.5 like neither. A GSM8K arm not learned or not reaching
the grid value is not read there.

**Edge cases the code writer runs before filing:** an anchor seed missing (single-seed, not validated); a zero or
sub-floor denominator in a share (unscored); equal seeds (spread 0: the noise floor decides); a gap equal to the
spread (not validated: strict); an anchor learned at no grid point (row unscored, card); NaN; no prompt qualifying.
Added with Fable's changes: K00 − K₀ zero or negative (share unscored); K11 − K₀ exactly half of K00 − K₀ (scored:
"exceeds" is strict); a grid value whose crossing comes at the first read (no lower bracket: the upper state is read);
both bracket states equally far from the grid value in log KL (the later step); a grid value never reached (not read
there); the two axes crossing at the same step (one save); an arm with fewer than 6,400 sequences (second pass); the
null missing (anchor 1 and own samples read without it, stated). The Job 1 rules (`own_accuracy`, `own_length`,
`gold_length`, `anchor1_learns`, `anchor2_learns`) and the selection rules are run against these cases in
`tests/test_qwen_updates.py`.

**Q3, not filed here** (Fable): the think-mode overlap row (Q3's switched-on set against Γ's think-mode set, over chance
and over a length-matched no-think set; domain alone predicts anchor 2's value, so it is not decisive) and anchor 2's
5th, differently phrased template. Both are named so Q3 can file them; neither is predicted or scored in Q2.

## 8. Decision tree (each branch approved with this plan)

- **Stage 0 or the gold curve misses** → stop, fix, rerun (class 2).
- **No prompt qualifies** → anchor 1 becomes the format anchor (§3).
- **Own samples below the floor at step 100** → rerun at 2e-5 once; still below → own samples unscored, card to the
  user (more samples or steps changes the task, which the re-plan forbids without asking).
