# Plan: the reuse score at the VPD featurization, known-answer items first (E226, cell P1.37)

*2026-11-20, definition-lead (writer agent). Card `reports/plans/2026-11-20_plan_p1-37-card.md`; detail in
`reports/plans/2026-11-20_plan_p1-37-vpd_appendix.md`; filed rules `experiments/kstar_vpd/results/predictions.json`.*

We read the reuse score R with VPD subcomponents as the variables, each decomposed matrix keeping a remainder. The
run first reads it on six items whose label is known by construction, then on E187's nine trained pairs. It is the
first reading at any level finer than heads that is checked against known answers. If the built new edits read below
the reuse items, the level can label the pairs for the paper; if not, it joins the coarse levels and neurons.

## What is run

One job, sharded over pods (`--shard k n`), with nothing trained:

- **Stage 0, alone on every shard: do-nothing.** F = M on E214's cue windows. It also measures the time per
  evaluation and projects the shard's hours.
- **Stage 1: six known items, E214's builders, on E214's windows.** These are new_few and new_thin (last position) and
  x2, x10, moved and rebuilt (copy24 held-out, every position). Each gets three searches: all of D, then each half of
  D, which sets the band.
- **Stage 2: E187's 68 saved states (nine pairs), E221's builder.** They use 512 read windows, last position, one
  search each. Stage 2 is read whatever stage 1 shows.

The measurement is `src/commute/kstar_vpd.py`:

- **Variables.** The embedding, the 38,912 subcomponents, one remainder per matrix (24), one graft variable per
  appended neuron (moved: 8), and the unembedding.
- **Split.** The least-squares split over all subcomponents, in fp64, with the outside part as each matrix's remainder
  change. The split is exact by construction.
- **F_K.** It is F's own forward minus each ablated variable's mechanism applied to (input minus its mean over D in
  F's run).
- **The grade s.** Analytic squared cosines.
- **K\*.** Attribution order, bisection of the shortest passing prefix, two re-rankings, then a chunk-removal polish,
  with 2,000 evaluations per search.

Per item it reports R (main: read positions; side: every position), f, the site-remainder share, the graft share and
|K\*|, each at the prefix set and the polished set.

## Expected values

- **Do-nothing.** No variable is changed. Every s is 1 within 1e-6, f = 0 and R = 1. The gates are exactly 0 when
  every variable is kept, because kept variables subtract exact zeros.
- **x2, x10.** Only layer 1's down_proj changes, so only its subcomponents and remainder can be in C.
- **moved.** The same site changes, and 8 graft variables score 0 by declaration. Moved is predicted to read low, and
  R1 is expected to fail on moved alone.
- **E187 states.** All 24 matrices change, so f is near 1. KL(F || M) and the update size repeat E221's load checks.

## Filed rules, in words

- **Band.** The largest gap between R on the two halves of D over the six known items. If that is 0, the card's
  spread (0.014) is used, and the summary says so.
- **R1.** The lowest R over the four reuse items exceeds the highest R over the two new edits by more than the band.
- **R1b (the rivals' rule).** The same over x2, x10 and rebuilt. If it holds, rival a. If new_thin reads at or above
  the lowest of those three, rival b. Anything else is no call.
- **P-moved.** R(moved) ≤ 1 − graft share + band. This holds by construction (grafts score 0 and s ≤ 1), so it is
  filed as a code check, not a prediction. **P-moved2** (drafted for the lead to check) says moved reads below the
  lowest of x2, x10 and rebuilt by more than the band.
- **T4 on the pairs (descriptive).** E221's rule: the per-pair R gap has the same sign on every pair and Spearman
  ≥ 0.7, against minus the update-size gap and against the held-model S3 gap.
- **Edge cases.** On the do-nothing state R1 cannot pass (0 against the 0.014 band) and T4 is "not read" (constant
  gaps). A missing item gives "not read". An item with KL(F || F_empty) ≤ 1e-6 reads "no behaviour" and no R.

## Cost and order

- **Estimate, from E221 until the rehearsal replaces it.** E221 spent 22 ms per evaluation at heads and MLP layers
  (`experiments/kstar_pairs/results/run_rehearse.log`: 2,030 evaluations in 45 s). A VPD evaluation does about five
  matrix products per decomposed matrix where E221's forward did one, so we assume 0.11 s.
- **Total.** 90 searches with four shards (6 × 3 + 68 + one per shard) at no more than 2,000 evaluations each come to
  at most 5.5 GPU hours, plus about a minute per item to load, split and grade (1.3 h).
- **Pods.** Four H100 pods, about 1.7 h each at about $3/h, cost about $20. That is under the gated lines ($60, 6 h),
  so the run is not gated.
- **Rehearsal (pod `commute-E226-rehearse-vpd`, H100 SXM).** It runs stage 0, new_thin and e58/cipher_s0 (5 searches,
  ≤ 30 min, about $1.5). It measures the time per evaluation, the evaluations each search uses, peak GPU and host
  memory, and the split checks. The every-position copy24 items (x2, x10, moved, rebuilt) are the likely memory peak
  and are not in that set; adding x10 costs one more item.

## Saved and downloaded (user amendment, 2026-11-20)

Each item writes two files. Nothing else changes: the readings and the filed rules are the same.

**`results/items/<item>.json`** holds every reading, plus the split's norm shares per matrix and over all 24 (appendix
§1).

**`results/large/<out>_<item>.npz`** holds the per-variable arrays:

- every variable's grade s, for the read positions and every position (fp32);
- which variables are changed (bool);
- per search, K\* membership for the polished set and the prefix set (bool);
- per search, the attribution scores of every ranking (fp32: the one that ordered the search and each re-rank).

**Size.** About 39,000 variables, so an item with one search holds about 0.9 MB before compression, and a known item
with three searches about 2.0 MB. That makes about 77 MB in all: 68 × 0.9 + 6 × 2.0 + 4 shards' do-nothing × 0.9.
That is about 8 s to download at 10 MB/s.

**What each pod brings back** (tar, then sha256 on both sides): `results/items/`, `results/large/items_*.npz`,
`results/stage0_<tag>.json` and `results/stage0_<tag>/`, `results/large/stage0_<tag>_do_nothing.npz` and the run log.

## Not run

- Neuron-level, heads-level or pruned-neuron readings (E214, E221, E217 own them).
- E187's scaled states, and E196's pairs.
- Any other split (adjoint, rescaling).
- Grouping dead subcomponents.
- More than one search order per item: the order spread is not read, only the half-D band.
