Update Decomposition · Γ summary · 2026-10-21

Γ and weight updates

Most of what an update does to the decomposition is done through Γ, not through the subcomponents it changes. Γ switching existing subcomponents on carries most of the gain on tasks the model already does, and subcomponents Γ keeps off carry it on new ones. What we cannot yet say is whether that switching is a real mechanism or the updated model's computation leaking in through Γ's input, and whether Γ can be retrained to keep a split update faithful.

A short companion to the Update Decomposition Log. Every experiment code links to its card there.

Why Γ is in the way

VPD writes each weight matrix as rank-one subcomponents plus a residual Δ, and Γ is the importance function that says which subcomponents matter on each input. Γ reads the model's activations. So after a fine-tune, Γ sees the updated model and changes which subcomponents it switches on, even if the subcomponents themselves are left exactly as they were (the do-nothing reference). Every question below comes from that one fact: Γ is part of how the update shows up, and also part of how faithfulness is judged.

Two threads

Q5 · main line

Γ as the route the update takes

Where does an update's gain go: strengthened subcomponents, re-switched existing ones, ones Γ keeps off, or Δ?

  • E4Under the original masks no arm's subcomponents carry emoticon; Γ's masks alone move the masked model most of the way. Every update switches on largely the same 150–200 existing subcomponents.
  • E5The changed subcomponents carry under 8% of the gain on every ladder task. Re-switching carries most of it for common next words; Γ-off subcomponents take over for rare ones.
  • E6Same target, same switched-on set; a different target, a different set. That set carries only about half the re-switching effect.
  • E12Copy tasks go through re-switching ("reveal"), random maps through Γ-off subcomponents ("create"). Only the route split tells them apart.
  • SGDThe first SGD component-training state is faithful and also mostly re-gating (2026-10-21, queued for the log). So far this is not an Adam artefact.
Q6 · Q1

Γ as a stale judge

Does the adversarial check fail because the released Γ no longer fits the updated model?

  • E15 · 0Not in the simple sense. The subcomponents the adversary turns down are inert one at a time at both models, but together they do twice the damage. The fragility is a joint effect.
  • E17Not cancellation either. Removing the adversary's share of the changes explains under a tenth of its damage. The rest is inferred to come from masking original subcomponents the updated model now leans on.
  • E15Retraining Γ brought the split fine-tune to the floor, but the same retraining knocked the unchanged model off it (up to 6.3), under two recipes. Its own attacker is weaker than the check's, 0.42 against 0.70 nats.
  • E10VPD's sparsity loss cannot tell operations apart while Γ is frozen: do-nothing and the split read identically.

The threads may meet. E17's analysis raised the possibility that the original subcomponents the adversary removes are the same set Γ switches on at the trigger. If so, the switching that carries the gain is also what makes the decomposition fragile. No run has measured that overlap yet; E18 reads it as an unscored extra.

Where this leaves us

Three tests decide it

  1. Mechanism or leak (E18, built, predictions filed, not run). On do-nothing states, apply the changed importance values only at the trigger, as one shared pattern, or as another task's pattern, and see how much of the re-switching effect returns. A leak drops the main line back to Q1; a mechanism makes re-gating the project's main result and a candidate signal for monitoring post-training.
  2. What the adversary leans on (E20, built, not run). Remove the adversary's share of the original subcomponents with the changes kept, binned by layer and by importance at W₀. This measures what E17 only inferred, and checks whether it is Γ's switched-on set.
  3. A Γ refit that leaves W₀ alone (E15, reopened 2026-10-21). An attacker matched to the check's, tested on the unchanged model first. Until W₀ stays at the floor, nothing the refit does to an updated model can be read.

Behind all three: every route split so far is of Adam states or finished updates, so Q11 (SGD against Adam) has to run before any of this counts as a property of the operation.
