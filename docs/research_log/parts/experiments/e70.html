On a counting pair whose answer is known, does removing the old count hurt the task that reuses it more than the task that needs a new one?

2026-11-03 · MATS cluster L40, debug QoS, $0 (jobs 50203 to 50363, then 50499) · experiments/pcfg_anchors · provisional, no independent check

The question. The benchmark line defines "reuses an existing capability" as: a linear readout trained on the pretrained model recovers it, and taking the readout's direction away breaks the fine-tuned behaviour. The removal clause had never been read on a pair whose answer is known by construction. The first reading's one regression direction did nothing, so a second try removed a direction chosen another way.

What we did. A small transformer is pretrained to count the letter a. Two fine-tunes of it: task P answers the count of a plus one (it reuses the count), task N answers the count of b (it needs a new one). We removed one direction from the residual at the answer position, block by block: first the regression probe's, then the direction along which the count moves the residual most (its covariance with the count). The share of gain lost is the state's extra drop in the log-odds of its answer, beyond the pretrained model's own drop, over the log-odds it gained in fine-tuning. The rule filed beforehand: if the reusing task loses more at every block read, one direction serves as ground truth; any reversal means it cannot.

What we found. The filed verdict is that one direction cannot serve as ground truth here. At block 6 the new task loses more than the reusing task, 0.17 against 0.07, and any reversal decides (second figure). At blocks 3 to 5 the reusing task loses 0.43, 0.78 and 0.88 of its gain and the new task 0.16, 0.34 and 0.49; accuracy after removal falls to 0.71, 0.48 and 0.29 for the reusing task and 0.98, 0.92 and 0.75 for the new one, so the new task is not spared. The direction costs the pretrained model up to 12 log-odds (first figure). With the regression direction removed a refit still reads the count at 1.0, which is why it did nothing; with the covariance direction removed the refit sits near the 0.3575 floor.

What it means. The main caveat weighs as much as the verdict. The random directions that set the band each hold about 0.005 of the residual's variance and this direction holds 0.30 to 0.78, so neither the pretrained model's loss nor the gap between the tasks reads as the count's causal role; neither the plan nor the filed list named this. The correlation of the two counts, -0.50, is an untested candidate for why the new task is hurt. Whether to try a same-kind removal that is not tied to the count is a question for you (section {{n:decisions}}); it would be the last amendment the rules allow.

Run
First reading: retrained the pretrained model and 20 fine-tuned states (two learning rates, five seeds, per task), six cluster jobs on an L40, about two hours, $0. Amendment 1: one job (50499, exit 0), 15 minutes, $0. No independent check.
Found
  • One direction cannot serve as ground truth here (filed verdict): the new task loses more than the reusing task at block 6, 0.17 against 0.07, though the reusing task loses far more at blocks 3 to 5.

  • The new task is not spared at blocks 3 to 5, and the -0.50 correlation of the two counts is an untested candidate.
