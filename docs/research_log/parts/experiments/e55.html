E55unscored

Can our tasks say whether post-training reuses a capability the model already had, and what ground truth could score a method that claims to?

2026-10-29 · reading and audit, no runs · reuse line · reports/plans/2026-10-29_plan_reuse-stage1.md

The question. Our labels "existing" and "new" for post-training have so far come from the decomposition's own behaviour, so a sceptic reads every result as a fact about VPD. The project adopted (2026-10-29) the definition of Jain, Kirk and Lubana: a model has a capability if a linear readout of it exists, and fine-tuning reuses it if the new behaviour is some function of what that capability computes. Stage 0 asks which of our tasks can be stated that way at all.

What we did. We read the paper and checked all fifteen tasks and updates in the repository against it: is the function and its inputs stated, is possession fixed in pretraining, is the capability relevant to the fine-tune. We also listed the paper's three settings, the numbers to compare against, and the cost of rebuilding the counting grammar, whose code was never released.

What we found. Six of fifteen state the capability and its inputs clearly; none fixes in pretraining whether the model has it. The emoticon and trigger-ladder tasks, which carry most of the commute line's results, cannot state a non-trivial function. On small token domains the definition is vacuous without held-out values, since a probe reads any 32-token map from the first layer. The paper's own thresholds are loose, its probes have no controls and its pruning has no random baseline.

What it means. Nothing measured so far can be scored against this definition. The first plan (revised after an independent review) rebuilds Jain's counting grammar on a small model (about 3M parameters, 5 to 6 H100 hours if rebuilt), chooses whether it already counts one letter, fine-tunes it to count another, and asks whether the new behaviour runs through the old count by what the model outputs and by swapping in the old count from another input. Pruning, reverse fine-tuning, steering and later VPD are scored on how often they agree. Whether a fine-tune that only looks up a new answer per word counts as reuse is a question for the user.
