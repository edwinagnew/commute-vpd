Does dividing each part's change by its weight change read the built edits and the trained pairs better?

2026-11-21 · cell P1.43 (filled), no independent check · experiments/kstar_vpd_norm

The question. The reuse score R, with VPD subcomponents as the variables, ranks the ten-fold reuse edit below a built new edit, and its gaps on the nine trained pairs follow update size (E226, E238). You asked for each changed part's loss to be divided by how much that part's weights changed, so this run asks whether that fixes the order of the six built edits and removes the link to size.

What we did. On E226's circuits and grades, for each changed part we divided its loss of write direction (one minus its grade) by its relative weight change, and averaged: N is one minus that mean. A part whose change only scales its output scores 0 on the ratio; a small change at right angles scores just under 1. We read N on the six built edits (four reuse, two new) and the nine trained pairs, on one cluster GPU for $0, with a pure-gain part and a pure-turn part run first as controls.

What we found. The filed rule holds: the ten-fold edit reads 0.233, above the few-neuron lookup at -2.04 and the thinly spread lookup at -3.21 (gap 2.27, noise band 0.081), and all four reuse edits sit above both new ones. But N is not a share: the ratio exceeds one on most parts of trained fine-tunes, because the grade counts every input equally while the weight ratio ignores inputs, so N on trained states runs from -4.21 to -1.39. On the pairs the reuse side reads higher on only 5 of 9, and the gap follows how much smaller the reuse side's update is (rank correlation -0.92; across 68 states N rises with update size, +0.62), the reverse of R. A version taking the ratio on inputs fails the filed rule (ten-fold edit 0.816 against 0.896 for the thin new edit).

What it means. Normalising fixes the built edits but swaps R's "smaller update reads as reuse" for "bigger update reads as reuse", as the cruder size division did, so neither separates reuse from update size yet. It rests on six built edits and nine pairs. No verdict on the definition.
