On real-text fine-tunes, which side of each built pair reads the higher write share over the needed variables?

2026-11-23 · cell P2.64, definition-lead, red-team: holds with caveats; premise check: doubtful · experiments/realtext_eb · finding card in the pending decisions

The question. Part 2 needs a reading that tells reuse from new on realistic fine-tunes, not only on built edits. Earlier saved fine-tunes of the 67M model come in pairs built so that one side needs what the base model already holds and the other needs something new. We asked which side of each pair the write share over the needed set reads higher, descriptively and with no filed prediction beyond two rivals.

What we did. We read the write share (the fraction of the needed variables' change that lies along the base model's own write at one positive gain) on eighteen saved fine-tunes: three pairs, three seeds a side. The pairs are a news topic label against a coin label, lowercase against reversed word order, and French against Yoruba. Each fine-tune was read beside a random update with its own per-matrix norms; do-nothing, which must read 1, and a variable swapped with itself, which must change no output, ran first and passed in every job.

What we found. On both readable text pairs the side built to need something new reads higher, on every seed: reversed order 0.061 to 0.063 against lowercase 0.025 to 0.028, and Yoruba 0.123 to 0.149 against French 0.065 to 0.082. Every fine-tune reads above its own random (the lowest gap is 0.008). The label pair is unread: the topic label's needed set has only 3 to 6 variables, under the filed bar of 100.

What it means. Either the reading misorders these fine-tunes, or at this size the built labels are wrong; no known answer on this model has tested them (the cue-lock run found no task that works), so the reversal is not evidence against the reading. Output change matches the reversal within each pair but not across the twelve text fine-tunes, and runs the other way within Yoruba's seeds, so it is not established as the cause. How unfamiliar each text is to the base model is the candidate worth reading next, and its all-position loss was not saved.

Run
Eighteen items on H100 pods, 427 to 748 seconds each, about $27.8 plus $3.0 for a lost pod and about $8.2 for its rerun; one run of four allowed.
Found
  • The built-new side reads higher on both readable pairs, every seed, and the order holds after subtracting each fine-tune's own random (gaps 0.049 to 0.052 against 0.013 to 0.017 on word order; 0.095 to 0.121 against 0.045 to 0.064 on language).
  • Neither filed rival holds: the reuse sides are not above their twins, and no side sits inside its random's range.
  • No single direction of the base prior explains both pairs (log10 prior -3.00 for lowercase and -6.31 for reversed order; -5.72 for French and -5.38 for Yoruba).
Bears on
Part 2: whether the reading detects reuse on realistic fine-tunes is not settled at 67M; premise check doubtful, since nothing independent of the reading fixes which side is reused.
