Can the frozen reuse definition read a natural pronoun task on the 67M?

2026-11-06 · stage 0 only, nothing fine-tuned · one cluster debug L40 job (54746), about 2 minutes, $0 · experiments/natural_tasks

The question. Every 67M task so far reads "unreadable", "does not apply" or "not through" under the frozen reuse definition (E116, E112), so no small-model task has a reuse label from outside the decomposition. We looked for a natural-text task the definition can read: choosing " he" or " she" to match a first name earlier in the window.

What we did. Before any fine-tune we asked the definition's first condition, possession: does a straight-line readout trained on Pile text recover the name's gender at the position where the pronoun is chosen, at some block before the last? A probe at 0.5 knows nothing and at 1.0 reads gender perfectly; the bar is 0.90, with a control probe on a random bit per name to show what name identity alone gives. A second candidate, "is" or "are" after "the N of the N2", was dropped before any run: 155 pattern windows in 32,768 Pile rows, 2 to 82 per cell.

What we found. The gender probe reads 0.53, 0.61, 0.73 and 0.87 over blocks 0 to 3 against the 0.90 bar, with the control between 0.50 and 0.54. The last block comes near but the definition does not count it, so possession fails and the task reads "unreadable". Every other stage 0 check passed.

What it means. The 67M does not hold a name's gender in a straight-line readable form at the pronoun before its last block, so no fine-tune ran and no re-gating share was read. This is a result about the small model, not a new rule: no amendment was made. A natural 67M task labelled outside the decomposition is still missing (E125 builds one).
