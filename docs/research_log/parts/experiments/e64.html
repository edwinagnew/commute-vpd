Can a readout over only the table's 64 values label "half-known", and does removing its direction cost the elicit fine-tunes more than the ciphers?

2026-11-02 · MATS cluster debug QoS, $0 (job 48611) · experiments/readout64

The question. "Half-known" rests on the original model's output ranks, the same thing the maps were built on (E54). E59 tried a decomposition-free label with a readout over all 50,277 tokens and it could not be read (Q5). The user approved a smaller one on 2026-11-02, as the causal check that "elicitation" now asks for.

What we did. Fit, on Pile text, a readout from each block's activations to only the pair's 64 table values, with a guard that it is specific to the keys. Then remove its direction from each of the 12 saved fine-tunes and compare how much of the gain goes for the elicit fine-tunes and for the ciphers. Because the original model itself misses E59's absolute bar (16 of 32 keys in the band where 24 were needed), "possessed" was made relative to the model's own possessed set, and two elicit values with too few Pile positions to fit were left out. The rules were amended after the code review, before any reading.

What we found. The run reads unreadable as filed: the readout missed its fit bar, and removing its direction did not cost the elicit fine-tunes more than the ciphers (elicit 0.045 below, where 0.2 above was predicted). Every block holds the elicit values and none the cipher's, but a next-token count table with no model nearly matches that (provisional).

What it means. The pair gets no causal label from this run, so "half-known" still rests on the original model's output ranks. The analysis has had no independent check yet. The user decides the line.
