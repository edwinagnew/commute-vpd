Is E54's "half-known" label independent of the decomposition: does a linear readout trained on ordinary text hold the half-known map's answers before the last block, and not the cipher's?

2026-11-02 · MATS cluster L40, debug QoS, $0 (job 48279 and a rerun) · experiments/jain_readout

The question. The reuse line (Q5) calls a key-to-answer map "half-known" because the original 67M model ranks the answer 2nd to 20th after the key (E54). That label comes from the model's output, the same thing the map was built on, so a sceptic can say the re-gating share only reads that. The user approved (2026-10-30) an independent label from Jain et al. 2024: a linear readout from a block's residual stream to the vocabulary, trained on Pile text and never on the task tables.

What we did. We coded one readout per block, trained on rows of the Pile disjoint from the task windows, and filed three predictions before running: the half-known map's answers are readable at an early block and the cipher's at none; removing the readout's direction takes away more of the half-known fine-tune's gain than the cipher's; and the last block's readout reproduces the construction. The first job stopped at stage 0 because the readout overfit; the amended rerun used fresh text and a measured limit, and ran to its hard cap.

What we found. The readout memorised its 15M tokens: the last block reads 0.37 nats over the linearised head on unseen text but 0.07 on text it had seen. It also missed the model's own ranks at the last block (11 of the 32 elicit values in the 2 to 20 band, where 24 were needed), so it could not say whether an earlier block holds the half-known values. No block held the cipher's values, which bears little weight on a readout this poor.

What it means. No answer: the independent label was not obtained, and "half-known" still rests on the original model's output ranks. The next asks are a small-vocabulary readout over only the table's values, or the graded ladder; the user approved the first (a Pile readout over only the pair's 64 table values with a key-specificity guard, then the removal test on the 12 saved fine-tunes, $0 on the cluster debug QoS). Before it, a $0 check of the model's own per-window ranks under the filed rule, which the E59 check found had never been measured.
