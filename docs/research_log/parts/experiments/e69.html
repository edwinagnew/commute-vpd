Qwen3-1.7B: does reinforcement learning on maths problems gain more than the same loop with shuffled rewards?

2026-11-03 · rehearsed on the MATS cluster L40 ($0, jobs 50067-50266); paid run on one H100 approved by you on 2026-11-03, $33 · experiments/qwen_rl · independent check done, no bug found

The question. The Qwen deliverable D2 asks for the same table for a supervised fine-tune and a reinforcement-learning update of the same model, and no reinforcement-learning update of Qwen3-1.7B existed. This run makes the first one, and a control that shows what the training loop does when the rewards carry no signal, so that qwen-decomp-lead can map and test them.

What we did. We trained the unchanged model on GSM8K school-maths problems three ways, 100 steps each, with 64 problems and 8 sampled answers per problem at a learning rate of 1e-6: reinforcement learning that rewards right answers (GRPO), the same loop with the rewards shuffled within each problem (the null, which should learn nothing), and supervised fine-tuning on the model's own correct answers. Each arm is one seed. We then scored all three on the same held-out problems, from GSM8K's test set and from GSM1K, with a strict grader (the answer must be in the exact format the reward wants) and a lenient one (format ignored). The change in the 196 decomposed weight matrices is saved at steps 1, 2, 5, 10, 20, 50 and 100; nothing here applies a map or reads the decomposition.

What we found. Under the strict grader, RL beat the shuffled-reward run on the same test problems by 3.2 points on the first seed and 6.4 on the second (standard error about 1, over problems, with weights fixed). With format set aside, the second seed stays at about 6.4 however long answers are treated. The first seed reads +1.25 on the answers all three states finish (the filed pool), +2.50 on whole answers and +5.53 if an answer past the window counts as wrong; the last two were read after the fact (first figure). The null gained 5.6 points on the first seed against a filed limit of 1.5 and 1.6 on the second, and we cannot say why. Fine-tuning on the model's own correct answers gains 2.6 and moves the model far less (KL 0.0017 against 0.194 for RL).

What it means. RL leads the null under the strict grader on both seeds, but two seeds cannot give the lead's size: the seeds differ by 5.2, 3.9 or 1.0 points depending on how long answers are treated, and nothing measured explains it. We do not claim the reward taught better maths, and RL's own gains of 9.0 and 7.1 points overstate what it added, since format is part of them. The shuffled run is a large change in behaviour without signal, not a do-nothing. The saved updates go to qwen-decomp-lead for the table (E75); you decided (2026-11-04) the RL row rests on these two seeds, with no third. An independent check reproduced the numbers on 2026-11-04.
