Does the route split's re-gating share read a key-to-value map the original 67M model already half-knows as "elicited", and a cipher on the same keys as not, where steering by one mean vector should fail on both?

2026-10-30 · MATS cluster L40, $0 planned · experiments/keydependent_elicit

The question. The re-gating line needs a reading that tells a fine-tune that elicits something the original model already does from one that teaches something new. E52 found that one added steering vector separates a copy task from a map, perhaps only because copying does not depend on the key. The user chose (2026-10-30) a pair where both tasks depend on the key.

What we did. Code and predictions are filed; the first cluster job has run (job 45963, below). Each of 32 keys (common word-like tokens) gets as value the word the original model itself ranks 2nd to 20th as its next token after the key, so the map is one it already follows weakly; the cipher uses the same keys with values the model gives almost no probability. Both are fine-tuned on E12's recipe (two seeds), the cipher read at the step whose update has the same size as the elicit map's. Each is then read two ways: steering with one mean vector (E52) and the route split's re-gating share r (E46).

What we found. Job 45963: every stage-0 control matched, but stage 1 stopped on its early check, the held-out elicit rate (the geometric mean over the elicit map's keys was 1.7e-3, below the 5e-3 floor, an averaging gap); the user lowered the floor to 1e-3 and the job is rerunning. No P1 to P3 reading yet. Filed: r reads higher for the elicit map than for the cipher; steering does not separate them and stays at or below 0.3 on both; the cipher's r moves by under 0.1 between the matched step and its own step. A prompting check was dropped because E52 Amendment 1 found no prompt format that works.

What it means. If r separates the pair while steering cannot, r is reading more than the key-independence of the task, which E53 could not show. A miss would say the earlier separation came from the task or its breadth. The rerun of the first $0 cluster job comes first.
