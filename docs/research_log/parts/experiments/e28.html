Does one fixed change of Γ's importance values explain re-gating on tasks it was never fitted to?

2026-10-22 · RunPod RTX 4090 · experiments/regating_tasks

The question. The decomposition splits each weight matrix into subcomponents ("pieces"), and its importance function Γ gives each piece a value from 0 to 1 on each input: how much that piece is used there. Alive pieces are the ones whose importance ever exceeds a small threshold, about a quarter of them. After a fine-tune, the frozen Γ reads the changed activations and switches on pieces it kept off before. This is re-gating, one of the project's two lines (Q5: is that switching a true description of how the model changed?). The fixed-shift hypothesis, adopted on 2026-10-22 as the line's working hypothesis, says the switching is mostly one fixed change to Γ's values at the trigger (the position where the task applies), the same for every input. It was drawn from three tasks in E18; this run tests it on seven new tasks, four word tasks and three key-value tasks.

What we did. We fine-tuned the 67M model for ten steps on four new word tasks: a trigger word followed by a target word, mined from ordinary text, which the original model already predicts with some probability. We did the same on three key-value tasks it lacks (original probability of the target under 0.002): after a marker, a word followed by itself (the copy task, 32 keys) or by a fixed random other word (a 32-pair and a one-pair cipher). Each fine-tune was read in the do-nothing state: the weight change is set aside in a residual the pieces leave out, so the pieces keep their original weights and only Γ reads the fine-tuned model. The switching effect is the rise in the target's log-odds when Γ's values come from the fine-tuned model instead of the original. Every number below is a share of what each input's own fine-tuned values give back of that effect: 0 is the original values, 1 is as good as the input's own.

Three named patterns of values stand in for Γ's at the trigger, with E18's names. The fixed change is one set of value changes, the same for every input: the fine-tuned model's average values over training inputs minus the original model's. The average pattern gives every input the fine-tuned model's average values, and we subtract what the original model's average values give, since averaging alone gives something back. Another input's values gives each input the fine-tuned values of a different input. The hypothesis fails a task if any of three tests fails. Test 1: the average pattern gives back under 0.5. Test 2: the fixed change, added to each input's original values but shuffled among the alive pieces, gives back over 0.2. Test 3: another input's values give back under 0.5, scored only where that other input's original values give back 0.2 or less.

What we found. All four new word tasks passed all three tests (first to third figures). On all three key-value tasks the average pattern gave back under half (first figure), narrowly on the one-pair cipher. The copy task was the surprise: we had expected it to pass, and it failed tests 1 and 3 (first and third figures). Test 2 could not fail there: the fixed change itself, on its own pieces, gave back almost nothing on the copy task and the 32-pair cipher, which is part of why those tasks fail, and left nothing for shuffling to lose (second figure). Test 3 was unscored on the two ciphers (third figure).

What it means. On one seed and at the trigger only, the hypothesis passes its three tests on the seven tasks the model already does (E18's three and the four new word tasks). It fails test 1 on all three key-value tasks, by 0.05 on the one-pair cipher, and test 3 is unscored on two of them. On the copy task the switching depends on the input; the key's identity is the natural reading, but no arm measured it, and the cheap next test is a fixed change per key. The user then scoped the hypothesis, tentatively, to one change per cue (2026-10-23).

Run
Ten-step Adam fine-tunes at rate 3e-5, seed 0, one per task, each read at the trigger on about 100 held-out windows; emoticon ran first as the control and reproduced E18 within 0.002, and two controls, a different target's fixed change and the fixed change moved to random pieces, gave back no more than 0.06 on every state (report). One RunPod job of 142 s, about $0.16, with predictions written down before the run.
