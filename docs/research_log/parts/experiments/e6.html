Do different updates that teach the same token switch on the same existing pieces?

2026-10-19 · RunPod RTX 4090 · experiments/recruit_test

The question. The decomposition splits each weight matrix into pieces (subcomponents), and its importance function Γ decides, for each input, how strongly each piece is switched on. In the task ladder (E5), most of an update's gain came from Γ switching the original pieces on differently, not from the pieces themselves changing; the project calls this re-gating. If re-gating is to describe an update (Q5, the "reveal" reading in which an update recruits pieces the model already has), the pieces it switches on should depend on what the update teaches. They should not depend on how the update was trained, nor appear for any change at the trigger.

What we did. On the emoticon task (after the first character of an emoticon, predict o), we took the 10-step fine-tune as the reference and set beside it six other updates. Two more teach o: the same fine-tune at a second seed, and a rank-8 LoRA on one matrix. Two fine-tunes teach a different token after the same trigger (<|endoftext|> and " http"); a random change of the fine-tune's size is the last. Component training (pieces trained on the task with Γ frozen) was a further o arm; only its net weight change was kept here, like every other update's. Each update was placed do-nothing: its weight change goes into the residual Δ, the leftover part of each weight that the pieces do not cover, and the pieces and Γ stay as released. Γ computes its importance values from the inputs to the model's matrices, and the weight change alters those inputs, so the only thing that can change is which pieces Γ switches on. An update's switched-on set is the pieces whose average importance at the trigger rises by more than 0.3 (on a 0 to 1 scale) over 73 held-out examples. Two sets are compared by their overlap: shared pieces over all pieces in either set (Jaccard; 0 none in common, 1 identical).

What we found. On this one task, which pieces are switched on followed the token taught far more than the method, though the two were not crossed: only fine-tunes were tried on other tokens, so method was compared only among updates teaching o. The fine-tune's set overlaps the LoRA's by 0.82 and component training's by 0.64. Its own second seed, a single rerun, gives a rough ceiling of 0.93. It overlaps the different-token fine-tunes' sets by only 0.04 to 0.05, though those sets are not much smaller (first figure). How much of the gain comes from switching does not depend on the token. Call the part of an update's gain on its own target that the original pieces produce under Γ's new importance values alone its re-switching share. It is 0.51 to 0.61 for every update, the different-token ones included (second figure). And the switched-on set is only part of that switching. Call the gain from Γ's new values alone the switching effect. Given those new values on the switched-on set only, the fine-tune keeps 40% of its switching effect; a random set of the same size keeps 1% (third figure).

What it means. The result is mixed. On this task, the switched-on set is a property of what the update teaches, so re-gating names something specific to the update. But the re-switching share says only how much a behaviour at the trigger can be routed through existing pieces at all, not which behaviour. And since the switched-on set carries well under all of the switching effect, matching sets shows which importance values moved, not what produces the behaviour; the prediction filed before the run, at least 0.40 for the fine-tune, was missed at 0.398. Whether the switched-on pieces are the model's existing machinery for o could not be tested here; the re-gating line took that question up later (E38).

Run
Seven updates on the emoticon task, one seed each except the fine-tune (two), each placed do-nothing and read on 73 held-out examples with the released pieces and Γ unchanged. One RunPod RTX 4090 run, 106 s, $0.26.
Found
  • Updates that teach o switch on largely the same pieces, whatever the method (overlap 0.64 to 0.82 against 0.93 for one rerun of the fine-tune, a rough ceiling); updates teaching another token after the same trigger share almost none (0.04 to 0.05).
  • Γ's switching alone gives about half or more of every update's gain, and the same amount for the different-token updates, so this share is not specific to the target; a random change of the same overall size (matched in Frobenius norm) does nothing.
  • Surprise, not plotted (see the report's Surprises): Γ reads every matrix's input at every position, so a LoRA on a layer-2 matrix also changed layer-0 importance values, and a check that assumed it would not rested on a wrong premise.
