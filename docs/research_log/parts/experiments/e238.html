Does another way of computing the reuse score order the built edits?

2026-11-21 · cell P1.42 (filled), no independent check · experiments/r_reanalysis

The question. The reuse score, with VPD subcomponents as the variables, ranks a built reuse edit (the ten-fold gain) below a built new edit, and its gaps on the nine trained pairs follow update size (E226, E232). You asked for the score or how it is measured to be reconsidered, so this run asks whether two changes to how it is computed, using only saved readings, fix the order of the six hand-built edits.

What we did. From saved grades and behaviour weights, with no GPU, we recomputed the score in two ways. One weights each part by how much the fine-tune's behaviour uses it. The other removes update size: it fits how far the score sits below 1 against update size over all 74 changed states, and scores an edit by how far it sits below that line. Each was read on the six built edits (four built as reuse, two as new) and the nine trained pairs, beside simple saved readings such as behaviour change from the base model.

What we found. Weighting by behaviour does not help: the ten-fold edit falls from 0.9755 to 0.9378, further below the thin new edit at 0.9974. With size removed all four reuse edits sit above both new edits, by 0.57 on the log scale against a noise band of 0.25, for any size-law slope from 0.89 to 2.9, and the reuse side reads higher on 7 of 9 pairs with no link to size left (rank correlation -0.37). Behaviour change from the base model also orders the six. A cruder version, dividing one minus the score by update size squared, orders the six built edits but puts reuse lower on only 4 of 9 pairs and overcorrects (correlation with update size -0.77), so it is not evidence for normalising; a per-part version (P1.37 run 2) is being prepared.

What it means. Removing update size is the change that helps, on the built edits and the pairs; weighting parts is not. It is a lead, not a pass: six edits, read on different inputs per side, a slope fitted on the same states, and behaviour change orders them too, so these edits cannot yet separate mechanism change per unit of weight change from behaviour change per unit of weight change. No verdict on the definition, which only you change.
