Does a reinforcement-learning update read differently from a supervised-fine-tuning update inside the decomposition, in one table?

2026-11-06 · from saved results, no new run, $0 · experiments/qwen_rl_reads · provisional, the one near-exception checked independently, the rest not

The question. The second deliverable ({{n:next}}) is the same table of readings for a supervised update (fine-tuning, SFT) and a reinforcement-learning update (RL) of the same model, Qwen3-1.7B on maths. Does anything in the decomposition tell the two kinds apart, beyond how big the update is?

What we did. We put every reading that E75, E93 and E104 made on the maths updates into one table: RL, the same loop with shuffled rewards (its null, an update that ignores what the reward says), and fine-tuning on the model's own correct answers (own-samples, one seed). A reading counts as a difference only when it exceeds the spread between two seeds. No new run was made.

What we found. RL reads like its shuffled-reward null on every reading, within seed noise. Own-samples differs from RL only through its far smaller output and through which matrices its update sits in. The one apparent exception, the overlap with the subcomponents switched on by a no-think reference set (RL 3.75 against the null's 3.05 to 3.15), is within counting noise: the two seeds share only half of it, and the gap is under two standard deviations. So no third seed is run.

What it means. Nothing in the decomposition yet tells an RL update from an SFT one on anything but size, and nothing tells RL from a run that ignores the reward. The columns for teacher training and the adjoint split are still to land (qwen-decomp-lead's), so the table is incomplete and this reading is provisional.
