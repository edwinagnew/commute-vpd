Can the clean-model table fail a bad placement of the right size, and does RL's update read as the fine-tunes do?

2026-11-03 · MATS cluster, $0 · experiments/qwen_rl_reads · provisional, no independent check

The question. D1 is a map on Qwen3-1.7B that keeps the decomposition faithful for a real update, judged by a test that can fail a bad placement. You chose the clean-model table as that test. D2 is the same table for a supervised update and a reinforcement-learning update. Does the table fail a bad placement of the update's size, and where does RL's update sit among the fine-tunes?

What we did. Nothing was trained. We ran three saved fine-tuning updates and two steps of RL's update through one clean table. The table scores a state, the original weights plus some part of the update, by how far its outputs are from the updated model's, as a fraction of the original model's distance (the ruler). The states were parts of the update, size-matched references, and three wrong changes at the update's size in each matrix: a random one, another update's, and the update with a random sign per matrix. We also read the shuffled-reward run through the same reads.

What we found. The table fails all three wrong changes of the right size on all five updates; the narrowest case is another update's change on the template fine-tune, with a gap of 1.7 times its bootstrap half-width (first figure). It still barely grades parts of the update against each other: the in-span part beats a random slice of its size by under 1 percent of the ruler (second figure). RL's update and its shuffled-reward run read the same filed labels, so those labels do not separate them (third figure).

What it means. D1's test can now fail a wrong direction at the update's norm, with one seed per state; size weighted by the inputs is untested, and "another update's change reads low on the fine-tunes" has no read. RL's update is not called learning here: the shuffled run also gained 5.6 points (E69). The next map test is teacher training with masks in its loss (E76).

Run
Reads on saved states, 128 maths rows of 256 tokens (64 for the template fine-tune), one job on a cluster card, $0; the control reproduced all eight stored numbers at gap 0. One amendment spent reading the wrong changes.
Found
  • Wrong changes at the update's norm fail on every update. Against our lean, another update's change reads well under the ruler on the first and gold fine-tunes (0.54 and 0.63); no read says why.
  • RL's masked rows read "deaf" like the fine-tunes' and its shuffled-reward run reads every label RL reads.
  • The remainder reads 1.9 to 2.6 times further than the rescaled update: the gap is about what size gives.
