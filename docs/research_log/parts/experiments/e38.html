Does the fine-tuned model itself use the subcomponents Γ switches on?

2026-10-27 · RunPod RTX 4090, MATS cluster L40 · experiments/recruitment_test

Partly: putting the switched-on subcomponents' trigger outputs back to the original model's values takes back about a fifth of the gain on emoticon and ` which`, and no other set we tried takes back any. Whether the set is special, or only the one whose outputs changed most, is not yet tested.

Run
E18's three tasks (emoticon, which-was, we-just), two seeds each, with a 10-step fine-tune to ` http` at the same triggers as the null. Each state was regenerated, and the switched-on set (the alive subcomponents whose importance at the trigger rises by more than 0.3) was subtracted from the real weights at every position (RunPod, about $0.23), then at the trigger only from both models, with a census of the set in Pile text (Amendment 2, cluster, $0). Amendment 3 (cluster, $0) put the set's trigger outputs in the fine-tuned model back to the original model's values, read beside 20 random sets, the ` http` set minus the switched-on set, and 20 sets already active at the trigger; five controls ran first, one tolerance amended after its first run stopped and before any result.
Found
  • Putting the set's trigger outputs back takes back 0.22 to 0.24 of the gain on emoticon and 0.18 to 0.20 on ` which`, and 0.04 to 0.05 on ` we`; the set is mostly the original model's own machinery for the target (60 to 96% of its pieces are followed by it in Pile text, against 2 to 8% of random pieces).
  • Nothing else takes back any: random sets, the ` http` fine-tune's set and sets already active at the trigger read 0.05 or less on the word tasks. This resolves Amendment 2, where the ` http` set's removal cost a tenth of the gain because the fine-tuned model leans on outputs that did not change. On emoticon, putting back the already-active pieces raises the target (about 0.2 of the gain); unexplained.
  • By the filed rule ` which` is specific, reversing the filed "not specific", ` we` is not (under 0.05), and emoticon is unscored because the active pool is too short to match; scored, it would read specific. The twenty active draws overlap heavily, and no comparison set is matched on how much its outputs changed, which the set's selection tracks.
