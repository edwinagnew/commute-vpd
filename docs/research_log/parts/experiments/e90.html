Can the definition of existing and new be applied to the old 67M tasks?

2026-11-05 · CPU stages plus cluster reads, $0 · experiments/new_vs_reuse · provisional; independent checks hold with caveat

The question. The "existing" and "new" labels the old 67M experiments assumed were never measured against the definition in section {{n:overview}}. If the definition cannot read them, findings that depend on those labels are weaker than the log says.

What we did. With the definition frozen, we took each old fine-tune and asked whether its gain goes when one named capability of the original model is removed, against a hand-built weight change that does the same job and should survive the removal. The removals were the original model's copying head, and the directions that carry token values at block 1, the latter read against random removals matched in variance. A row first has to pass the admissibility rule, which asks that reading the capability beats ignoring it on held-out inputs. We also wrote the definition down for Qwen's three example updates, on paper.

What we found. The table's lead column reads the copy tasks "reuses C" and the tasks built to be new "no C listed"; constant answers do not apply. Only the copying pair reads as assumed through a located mechanism: with the copying head off, the copy state loses about half its gain (0.47 to 0.56) and the lookup state none, which repeats the measurement the label came from. Under direction removal, the filed rule at block 1 separates the 32-key copy map from the random map by a difference of degree on one pair of tables (0.499 and 0.530 over a band of 0.413, against 0.370 and 0.359). The next block has no working control, and nothing saved shows this means more than that the copy map needs its input token. Tasks labelled strengthening get no reading.

What it means. For the second question's "existing" side the 67M has no reading beyond copying, so the labels we relied on stay assumptions, and a circuit built from old parts still reads as reuse. You decided on 2026-11-05 that a label needs a located mechanism, or a removal of the value direction that clears its controls and shows more than a token-reader loses. On the old tasks only the copying pair qualifies; its copy maps read "needs the input token" and the rest are reported unreadable, with the reason. Constant-answer tasks stay "does not apply", with two behavioural numbers beside the verdict (the original model's prior on the target and the fine-tune's gain); there is no fourth verdict. Locating mechanisms is a separate piece of work for a lead you may start; it has not started. The follow-up on saved states (E95) found a hand-built reader that needs only the token loses more under the removal than any state, so "reuses token identity" is not shown to mean more than needing the token.

Run
Stage 0 (text only), then stages 1 and 2 and Amendments 1 and 2 on the old 67M states, on the cluster and CPU, $0; the Qwen check is paper only. The input-dependent ladder and emoticon tables found no version that kept the old target, and the two-sided lowercase state read "not specific".
Found
  • One row reads as assumed through a mechanism, the copying pair; the pair's lookup side is a control only, since admissibility lists no capability for it.
  • Removing token-reading directions costs the copy map more than a random map at block 1, by degree, and again on a second table pair (E95), though a hand-built reader that needs only the token loses more; the filed lean missed on the copy rows and stands, and "does not reach" reads wrongly on the random map.
  • Rows with a constant answer (lowercase, emoticon, ladder, many cues) read "definition does not apply"; no strengthening task has a reading.
