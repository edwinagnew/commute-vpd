Can the definition of existing and new be applied to the old 67M tasks?

2026-11-05 · CPU stages plus one cluster read, $0 · experiments/new_vs_reuse · provisional, not independently checked

The question. The "existing" and "new" labels the old 67M experiments assumed were never measured against the definition in section {{n:overview}}. If the definition cannot read them, findings that depend on those labels are weaker than the log says.

What we did. With the definition frozen, we took each old fine-tune and asked whether its gain goes when one named capability of the original model is removed, against a hand-built weight change that does the same job and should survive the removal. The removals were the original model's copying head, and the directions that carry token values at block 1. A row first has to pass the admissibility rule, which asks that reading the capability beats ignoring it on held-out inputs. We also wrote the definition down for Qwen's three example updates, on paper.

What we found. Only the copying pair reads as assumed through a located mechanism: with the copying head off, the copy state loses about half its gain (0.47 to 0.56) and the lookup state none. Direction removal does not tell new from old: tasks built to be new (the cipher, the random map) read "reuses" where admissibility does not already rule them out, and rank-1, built to be old, is unreadable on a margin of 0.02. Tasks labelled strengthening get no reading apart from the copy tasks. On Qwen the definition writes for the answer-format template only, is silent on the invented biographies, and finds no one capability for reinforcement learning.

What it means. For the second question's "existing" side the 67M has no reading beyond copying, so the labels we relied on stay assumptions. The table's verdict column leads with "no C listed" on rows admissibility rules out and shows the filed read beside it. A graded order of the shares at block 1 follows the assumed labels, but it was not filed and other readings of it break it, so it is not a finding. Nothing here has had an independent check.

Run
Stage 0 (text only), then stages 1 and 2 on the old 67M states, on the cluster and CPU, $0; the Qwen check is paper only. The input-dependent ladder, emoticon and lowercase tasks were coded: the ladder and emoticon tables found no version that kept the old target, and the two-sided lowercase state read "not specific".
Found
  • One row reads as assumed through a mechanism, the copying pair; the pair's lookup side is a control only, since admissibility lists no capability for it.
  • The random map, copy map and cipher read "reuses" under direction removal, the reverse of one filed lean, which stands as read; rank-1 reads unreadable by 0.02.
  • Rows with a constant answer (lowercase, emoticon, ladder, many cues) read "definition does not apply"; no strengthening task has a reading.
Bears on

Moved on
