Every pair of fine-tunes we test on has already been looked at. Should the paper's main claim about the share be tested once on a new pair that no agent can read beforehand?

Why this matters. The measures were chosen with the test pairs in plain view, so a good result on them could partly reflect that. A clean test needs a pair nobody has read until the claim is fixed. All agents share one account and disk, so the trained weights have to be encrypted to a key only you hold. The share is the part of a fine-tune's gain that appears when we keep the decomposition's original pieces and change only which ones switch on.

What would run if you approve. One new task on the small model: the fine-tune says one label word when a bracket is still open and another when it is closed, and its twin gets the same text with labels shuffled. Three copies of each, about 20 minutes on the free shared cluster (an estimate). You make a key on your laptop and start the job yourself. A scorer committed before training reads the weights once, after the rest of this part is done, and prints one number: the real fine-tunes' mean share minus the twins'. Zero means the share does not tell them apart. First, the job checks that the original model tracks open brackets at all.

The four choices. The file named at the end of this card gives the detail.

  • What the number tests. Option a: real against shuffled twin, the share's hardest case. Option b: a copy-a-word pair against a recall-per-word pair, the share's best case and the kind we have measured most.
  • The task. Option a: bracket order. The original model already tracks brackets, so it tests a new last step on old knowledge against memorising, not full reuse. Option b: another task you name.
  • How the weights are held. Option a: trained on the shared cluster and encrypted as written, to your laptop's key (needs gpg on both machines). Option b: trained on a cloud machine you start, a few dollars.
  • If no definition of reuse is adopted in time. Option a: the number is reported with no verdict. Option b: it waits.
