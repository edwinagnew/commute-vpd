Question for you · reuse · new 2026-11-02

Nothing runs until this is decided.

Train VPD's full decomposition of the counting model, when a barely trained one already scores every fine-tune right?

The question. The reuse line wants to score VPD on 21 small fine-tunes of a counting model, some that reuse the old count and some that learn a new one, where we set the truth by construction. Training the full decomposition would take about 56 hours on the cluster, at $0. As a free check we read the same fine-tunes on a decomposition trained for only 400 of its 400,000 steps. It already labels all 21 right under the rule we filed in advance, the outcome that rule calls a tie.

The evidence.

  • Fine-tunes that reuse the old count read near 0, those that learn a new count near −0.05 (cut-off −0.018), against 0.77 and 0.24 for the elicit and cipher fine-tunes on the 67M. This gap is far too small to be the effect VPD is meant to measure.
  • The identity-prompt fine-tunes, which must reach 0.5, read about 0.07: the positive control says "none", as it should for an untrained decomposition. It changes no outcome today.
  • We expected the gap to follow the answer token being read out. On two fine-tunes of each kind it follows the fine-tune instead: the new-count ones read −0.87 and −1.07 at the other kind's token, the reuse ones −0.19 and −0.01. The cause is not established; the token explanation was tested and did not hold.

Options.

  • A. Drop this run (recommended). Nothing runs, so VPD gets no score on the counting set. What we would learn is in hand: there VPD can at best tie the cheap methods, and a tie comes free. Next, a plan to score VPD on the 67M and Qwen fine-tunes, whose decompositions exist, where a VPD label can disagree with the others.
  • B. Run one 24-hour job, then read. About 170,000 steps on one shared L40, $0. It tells us whether a decomposition of this small model trains at all (the identity-prompt reading, and how close the masked model gets to the real one). Worth it only if we want one for later. The next two jobs would go ahead only if an identity-prompt reading reaches 0.25 or the masked model's error halves (bars from our advisor, not filed).
  • C. Run the whole thing, after amending the rule. Three 24-hour jobs, about 2.5 days of one of 8 shared L40s, $0. The rule changes first so that a tie counts only if the identity-prompt control holds, otherwise "tie, apparatus unverified". It most likely ends in a tie. The one informative outcome, VPD mislabelling a fine-tune the cheap methods get right with the control holding, our advisor puts at about 15%.

Recommendation: A. B if you want a trained small decomposition for its own sake; C if VPD's result on this exact set matters regardless of the tie.

How should the scaled adjoint split's loss of behaviour be worded?

The question. At the same update size a faster SGD run keeps 0.08 to 0.09 more of the behaviour than a slower one, on both seeds. The size-only test could not be scored: a shrunk update loses the behaviour itself.

Options. (a) Reword: "the split keeps less as training goes on; at matched size the path adds about 0.08; size alone untested". (b) Design a size-only test that keeps the behaviour. (c) Drop the claim. Recommendation: (a); the splits are no longer the line's map.
