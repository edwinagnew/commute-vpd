### Lubana, Bigelow, Dick, Krueger, Tanaka 2023, Mechanistic Mode Connectivity (arXiv:2211.08422). Status: main text read (pp.1-9; appendices not read)
- **Matches the list?** Yes (ICML 2023 version v3).
- **Definition, in the authors' words:**
  - p.3: "we argue two models are mechanistically similar if they utilize the same attributes of an input to make their predictions (e.g., shape or background). This can be assessed by transforming an input to alter some attribute of interest and thereafter checking if the two models under consideration make the same predictions on these transformed inputs."
  - p.3, Definition 3 (Invariance): "We say f(.; θ) is invariant to unit intervention Ai if counterfactuals generated by Ai do not increase its loss, i.e., L(f(D; θ)) = Eα∈Zi L(f(E(D; Aα i ); θ))."
  - p.4, Definition 4 (Mechanistic Similarity): "Consider a set of unit interventions Ab := {Ai}, where i ∈ [m]. For parameters θ, denote the subset of interventions that f(.; θ) is invariant to as I(θ) ⊂ Ab. Then, f(.; θ1) and f(.; θ2) are called mechanistically similar if I(θ1) = I(θ2)."
  - p.2: "claiming similarity if the models are invariant to the same set of interventions."
  - Fine-tune same/new (p.6-7, empirical): "when linear mode connectivity does not hold, the fine-tuned models behave differently on counterfactuals, i.e., are mechanistically dissimilar to the pretrained model." And p.2: "if a model has learned to rely on spurious attributes during pretraining, our results imply mere fine-tuning on some 'clean' dataset may not improve its robustness."
- **What counts as the thing:** a mechanism = the set of input attributes (latent factors of the data-generating process) to which the model is invariant; no internal component is identified.
- **What the original model already having it means:** the pretrained model's invariance set I(θ); the fine-tune "keeps" the mechanism if I(θ_ft) = I(θ_pre) (Def. 4). Mechanisms are not located in weights.
- **Kind:** formal definition (Defs. 1-5), plus a conjecture (lack of linear connectivity implies mechanistic dissimilarity; shown only for a 1-hidden-layer model, App. F, not read) and experiments.
- **What it assumes:** a known data-generating process with independent, invertible latents (p.3) and a chosen set of interventions; synthetic cue datasets (CIFAR-10/100 with box cues, Dominoes); image classifiers (VGG-13, ResNet-18).
- **Is it about the fine-tune or about the task?** About the pair of models, relative to a fixed list of interventions. Two fine-tunes of one model with the same behaviour can differ, because it compares invariance sets, not behaviour (yes, they can differ; e.g. their Table 1 shows fine-tuning variants with the same clean accuracy and different cue reliance). Result depends on the intervention set chosen.
- **Objection:** authors' own statement (p.9): "Future work can involve use of counterfactual generators based on modern generative models (Thiagarajan et al., 2021) to extend our synthetic data experiments and corroborate our claims in naturalistic settings." Also p.9: "our claims do not preclude possible linear connectivity of mechanistically dissimilar models". (Reader's) Needs an explicit list of interventions and a generative model of the data, so it does not transfer to language-model fine-tunes where no such latents are known; it says nothing about internal components.

### Panigrahi, Saunshi, Zhao, Arora 2023, Task-specific Skill Localization in Fine-tuned Language Models (arXiv:2302.06600). Status: main text read (pp.1-9; appendices not read)
- **Matches the list?** Yes (ICML 2023).
- **Definition, in the authors' words:**
  - p.1: "This paper introduces the term skill localization for this problem". p.2: "recent papers have approached by equating 'skill' with the ability to perform a specific fine-tuning task."
  - p.2, Eq. 1: "A grafting of θft in the region γ onto θpre is defined as θft(γ) = γ ⊙ θft + (1 − γ) ⊙ θpre." Desiderata: "Good Localization: the region γ is sparse, i.e. ∥γ∥0 is tiny" and "Skill retention: LT (θft(γ)) ≈ LT (θft)".
  - p.2: "while γ denotes the location of the skill, γ ⊙ (θft − θpre) gives a succinct representation of the core skills acquired."
  - Same/new: no definition. The skills are called "newly-learnt" (p.1 abstract) and fine-tuning is "quick to acquire new 'skills'" (p.1); no test of whether a skill pre-existed.
- **What counts as the thing:** a skill = a sparse set of parameters (about 0.01% of parameters) whose fine-tuned values, grafted onto the pretrained model, recover the fine-tuned model's task performance.
- **What the original model already having it means:** not addressed (the pretrained model is only the base values everywhere outside the region).
- **Kind:** operational measure only (grafting mask optimisation) with experimental findings.
- **What it assumes:** a downstream task with a metric; a fine-tune obtained with SGD (p.4: "fine-tuning with AdamW does not contain sparse grafted models with good performance" unless an l1 penalty on parameter movement is added); few-shot GLUE-type classification with RoBERTa/GPT-2.
- **Is it about the fine-tune or about the task?** About the fine-tune (the mask depends on θft), but only through the update θft − θpre restricted to a region; two fine-tunes with the same behaviour can have different regions (yes; the paper itself finds AdamW and SGD differ, p.4). Task overlap between regions is read as task similarity (p.8, Fig. 8).
- **Objection:** authors (p.9): "We hope our first-cut method will improve with further work". On method: "Exploring other ways to learn the regions, perhaps directly from the pre-trained model, is an interesting open question." (p.4). (Reader's) It localises where the change is, not whether it is a reuse or a new mechanism; a graft that works shows sufficiency of the change, not that the pretrained model lacked the mechanism.

### Lee, Bai, Pres, Wattenberg, Kummerfeld, Mihalcea 2024, A Mechanistic Understanding of Alignment Algorithms: A Case Study on DPO and Toxicity (arXiv:2401.01967). Status: main text read (pp.1-8, all)
- **Matches the list?** Yes (v1; authors on the paper are as listed plus others, title as listed).
- **Definition, in the authors' words:** no definition given. Nearest statements:
  - p.1 abstract: "capabilities learned from pre-training are not removed, but rather bypassed."
  - p.2: "DPO does not remove the capability of generating toxic outputs, but learns an 'offset', distributed amongst its layers, to 'bypass' the regions that elicit toxicity."
  - p.5: "every parameter in GPT2 and its counterpart in GPT2DPO has a cosine similarity score greater than 0.99 and on average a norm difference less than 1e-5."
  - p.6: "GPT2DPO has learned an offset, δx, such that the residual stream avoids regions that promote toxicity, γ(MLP.kToxic)."
- **What counts as the thing:** toxicity-promoting MLP value vectors (found by cosine similarity to a linear probe, p.3) and the "activation region" of their key vectors (Eq. 3, p.5).
- **What the original model already having it means:** the pretrained model's toxic value vectors; they are still present and unchanged after DPO but are activated less. Reuse/new is not defined; the finding is that the fine-tune adds a bypass offset rather than editing the existing components.
- **Kind:** experimental finding only (case study; metrics are activation drops and cosine similarities).
- **What it assumes:** a behaviour (toxicity) whose components can be located by a probe; GPT2-medium; DPO with KL regularisation to the reference model (p.8: the authors "hypothesize that the minimal changes distributed across all layers is due to the KL-divergence term").
- **Is it about the fine-tune or about the task?** About the fine-tune plus the base model; the authors themselves note a different fine-tune (Jain et al. 2023, no KL term) gave a different mechanism ("wrappers" at late layers, p.8), so two fine-tunes can differ (yes).
- **Objection:** authors p.8: "We find this difference in model training behavior interesting, and conjecture that the KL-divergence term may play a role in this difference." (No explicit limitations section.) (Reader's) Single model, single behaviour, one DPO run; "bypass" is shown by activation drops and one un-aligning intervention, with no threshold for when a change counts as a bypass versus a modification.

### Wang, Hu, Du, Cheng, Wang, Zou 2025, Towards Understanding Fine-Tuning Mechanisms of LLMs via Circuit Analysis (arXiv:2502.11812). Status: main text read (pp.1-9; appendices only grep-checked)
- **Matches the list?** Yes (ICML 2025). Note the list says "Wang et al. 2025" and the first author is Xu Wang.
- **Definition, in the authors' words:**
  - p.1: "circuits are specific subgraphs that perform identifiable functions". Circuits found with EAP-IG (p.3), keeping 5% of edges (p.4).
  - Faithfulness (p.3): "Faithfulness = (1 − |F(M) − F(C)|/F(M)) × 100%". Robustness (p.3): "Robustness(p) = JE(G0, Gp)" (Jaccard similarity of edges under dataset perturbation).
  - Change measure (p.5): "ΔS = (1/n) Σ_{t=0}^{n−1} Δs_{t→t+1} / S0 × 100%" where Δs counts "nodes or edges that change from checkpoint t to checkpoint t+1".
  - Same/new: no threshold. p.1 abstract: "circuits maintain high node similarity before and after fine-tuning, their edges undergo significant changes". p.2: "new circuits emerge after fine-tuning, with edge changes playing a more significant role in this process." p.9: "fine-tuning primarily modifying edges rather than merely introducing new components to form new circuits."
- **What counts as the thing:** a circuit = the set of nodes and edges kept by EAP-IG at 5% of edges, with faithfulness above about 70-80%.
- **What the original model already having it means:** the circuit found in the pretrained model on the same task data (p.4: faithfulness above 80% for most tasks at checkpoint 0); the fine-tune "reuses" what overlaps in nodes, "builds new" in edge changes. No cutoff is stated.
- **Kind:** operational measure only (node/edge change counts between circuits) with experimental findings.
- **What it assumes:** tasks where the base model performs poorly but a circuit is still recoverable (p.2: "this approach consistently finds circuits with high faithfulness, even though the two models differ markedly in performance"); arithmetic-style tasks with a corrupted counterpart; Pythia-1.4B, GPT-Neo 2.7B, OPT 6.7B; thresholded edge set.
- **Is it about the fine-tune or about the task?** Partly the task: the circuit is defined on a task dataset and the edge selection is a top-5% threshold. Two fine-tunes with the same behaviour can give different edge changes (yes; the appendix compares LoRA, AdaLoRA, IA3 and full fine-tuning, App. F-G, only grep-checked).
- **Objection:** authors p.9: "Although our work focused on math tasks, applying circuit-based methods to more tasks would further validate the generality of our insights." (Reader's) Circuit membership depends on the 5% edge cutoff, so "node similarity high, edges change" has no stated threshold; and a circuit with high faithfulness in a model that fails the task (low accuracy) means the circuit is not what produces the correct answers, which weakens reading edge changes as new mechanisms.

### Chhabra, Zhu, Khalili 2025, Neuroplasticity and Corruption in Model Mechanisms: A Case Study of Indirect Object Identification (arXiv:2503.01896). Status: main text read (pp.1-9; appendices not read)
- **Matches the list?** Yes. (The wording in Wang et al. cites it as "Chhabra et al., 2024"; the arXiv posting is Feb 2025.)
- **Definition, in the authors' words:**
  - p.1 abstract: "Underlying mechanisms are amplified across task-specific fine-tuning".
  - p.4: "task-specific fine-tuning enhances the underlying mechanisms of circuits without introducing novel mechanisms, even in longer training scenarios. The enhancement stems from two sources: (1) amplified capabilities of existing circuit components and (2) emergence of new components that replicate prior mechanisms. We term this phenomenon Circuit Amplification".
  - p.6: "toxic fine-tuning alters the prior mechanisms of the circuits instead of introducing new mechanisms for suppressing performance on the task."
  - Circuit evaluation (p.3): "using the minimality, completeness, and faithfulness criteria (Wang et al., 2022; Prakash et al., 2024)"; "faithfulness is measured by the average logit difference ... |F(M) − F(C)|".
  - Neuroplasticity (p.2-3): "the ability of the model to adapt and regain conceptual representations (Lo et al., 2024). We extend this definition to include the ability of a model to relearn corrupted concepts/mechanisms."
- **What counts as the thing:** a mechanism = the function of a class of attention heads in the IOI circuit (Name Mover, S-Inhibition, etc.), judged by attention patterns and logit attribution.
- **What the original model already having it means:** the Wang et al. (2022) IOI circuit, whose head classes are checked in the fine-tuned model; "novel mechanism" is a head performing a function absent from that list. Table 1 gives |F(C) − F(C_M^GPT2)| as the contribution of new components.
- **Kind:** informal definition (a coined term, "amplification") plus experimental findings.
- **What it assumes:** a task with a known, hand-derived circuit (IOI) in GPT-2-small that the base model already does; ACDC-style automatic discovery was avoided to "stay faithful to the original work" (p.3).
- **Is it about the fine-tune or about the task?** About the task and its pre-labelled circuit, read before and after fine-tuning. Two fine-tunes that gain the same behaviour could differ (unclear): only one task-specific recipe is tested, plus corrupted-data variants.
- **Objection:** authors p.8-9: "Our work focuses on a specific architecture and two task on it. Additional work is needed to scale/generalize our results for other architectures/tasks." (Reader's) "Novel mechanism" is decided by whether a head matches a function in a pre-existing list, so a mechanism outside the list cannot be recognised; the Wang et al. 2025 paper above reports the opposite conclusion on tasks where the base model is weak.

### Merullo, Eickhoff, Pavlick 2023/2024, Circuit Component Reuse Across Tasks in Transformer Language Models (arXiv:2310.08744). Status: main text read (pp.1-9; appendix I.3 and J, K read; rest not read)
- **Matches the list?** Title and authors match; the paper is not about fine-tuning. It compares two tasks in one pretrained model (GPT2-Medium). Included for the "reuse" criterion.
- **Definition, in the authors' words:**
  - p.2: "we study whether LMs reuse model components across different tasks to accomplish the same general behaviors".
  - p.4: "thresholding at the 2% most important heads for each circuit, we find that 25/32, or 78% of the circuit is shared."
  - p.7: the top 2% is "the minimal threshold for containing the in-circuit components for both tasks".
  - p.2 fn.2 / App. I.3 (p.28): "Putting an exact number on how similar two circuits are is a very complex task that we do not attempt to fully answer in this paper." and "we do our best to place an accurate number on the overlap as the proportion of shared nodes in the circuit."
  - Functional reuse: "We are thus interested in whether the LM views these tasks as related at the algorithmic or implementation level." (p.4)
- **What counts as the thing:** a circuit = the attention heads found by path patching at top 2% importance per stage, with roles (mover, duplicate/induction, inhibition, content gatherer).
- **What the original model already having it means:** not applicable (no fine-tune). "Reuse" = the same heads fill the same role on a different task, plus an intervention that makes one circuit behave like the other (accuracy 49.6% to 93.7%, p.1).
- **Kind:** operational measure only (proportion of shared top-2% heads) plus experimental finding.
- **What it assumes:** two tasks that share an algorithm; a single model; path patching on a task dataset. App. J (p.28): overlap falls with scale: "In GPT2-Large, five of these heads overlap, but none overlap in GPT2-XL" among top-10 heads.
- **Is it about the fine-tune or about the task?** About the task pair, not any training. Not applicable to the fine-tune question; as a measure it would depend on the dataset used for each circuit.
- **Objection:** authors p.29: "A limitation of this study is that we are not able to confirm the generality of the circuit beyond the tasks studied here." (Reader's) The 78% figure rests on a 2% cutoff, and the paper's own scale check shows head-level overlap can vanish while head function is retained, so a head-identity overlap is an unstable criterion.

### Jain, Lubana, Oksuz, Joy, Torr, Sanyal, Dokania 2024, What Makes and Breaks Safety Fine-tuning? A Mechanistic Study (arXiv:2407.10264). Status: main text read (pp.1-10; appendices not read; 66 pages)
- **Matches the list?** Yes (arXiv v3, Aug 2024; NeurIPS 2024 paper).
- **Definition, in the authors' words:** no definition given of reused/new mechanism. Nearest statements:
  - p.1 abstract: "these methods minimally transform MLP weights to specifically align unsafe inputs into its weights' null space."
  - p.7, Observation 2: "The column-space of the transformation, C(ΔW), is more aligned with the null-space N(W_IT^T) than it is with the column-space C(W_IT). Hence, samples processed by the transformation versus not will have rather distinct activations, enabling clustering." (ΔW = W_ST − W_IT.)
  - p.7: "a sample processed by ΔW will have a component that cannot be computed by W_IT itself".
  - p.6, Observation 1 / Eq. 2: clustering measured by "τ(x, μ_S, μ_U) = ||â(x) − μ_U||_2 − ||â(x) − μ_S||_2".
  - p.10: "our results echo the claims in recent work that state safety fine-tuning minimally alters a model".
- **What counts as the thing:** the safety "transformation" ΔW of the MLP layers, characterised by which input subspace it acts on (row space of ΔW) and where it writes (null space of W_IT^T).
- **What the original model already having it means:** the instruction-tuned weights W_IT; the fine-tune's change is called new where it writes into a subspace W_IT cannot produce (p.7 above). Only a geometric reading; no threshold.
- **Kind:** experimental finding only (with a geometric measure: projection of left singular vectors of ΔW onto N(W_IT^T)).
- **What it assumes:** a synthetic PCFG-and-bijection data setup with minGPT (and Llama-2/3 chat vs base as corroboration, 500 safe/unsafe instructions); changes concentrated in the last MLP layers; a distinction between safe and unsafe inputs.
- **Is it about the fine-tune or about the task?** Fine-tune: it reads ΔW directly. Two fine-tunes with the same behaviour could differ (yes; the paper itself finds SSFT, DPO, unlearning, and medium vs small learning rates give different cluster separations, Fig. 3-5, p.6-8).
- **Objection:** no limitations section found in the main text (pp.1-10). Authors p.10: "Though we primarily focus on a synthetic, but well grounded, abstraction of real language data, several of our claims directly transfer to more realistic setups". (Reader's) Evidence for the Llama case is on 500 hand-built instructions; "orthogonal to W_IT" is measured at one layer's first MLP and the authors note (p.8) the layerwise claim must be extended to the full model (App. C.1, not read).

### Extra paper 1. Minder, Dumas, Juang, Chughtai, Nanda 2025, Overcoming Sparsity Artifacts in Crosscoders to Interpret Chat-Tuning (arXiv:2504.02922). Status: main text read (pp.1-10; appendices not read)
- **Found by search; not on the original list.** Version v4 (NeurIPS 2025).
- **Matches the list?** n/a (added).
- **Definition, in the authors' words:**
  - p.1: "Model diffing is the study of how fine-tuning changes a model's representations and internal algorithms."
  - p.2: crosscoder latents are classified as "chat-only, base-only, and shared"; "Lindsey et al. [2024] identify chat-only latents by looking at the norm of the latent directions – if the latent direction of the base model has zero norm, this indicates that the latent is chat-only."
  - p.3-4, Eq. 3 and text: relative norm difference Δnorm; "we classify latents as base-only (0–0.1), chat-only (0.9-1.0), or shared (0.4-0.6)."
  - p.5, Latent Scaling: "ν_j = β_j^base / β_j^chat ... A value near zero indicates a chat-specific latent, while a value near one suggests the latent is equally present in both models." Chat-specific = chat-only with ν^ε < 0.2 and ν^r < 0.5 (Fig. 1 caption, p.4).
  - p.2 (on prior work): "these studies have hypothesized that fine-tuning primarily shifts and repurposes existing capabilities rather than developing new ones, conclusive evidence for this claim remains elusive."
- **What counts as the thing:** a feature = a latent direction (one per model) in a shared crosscoder dictionary trained on the layer-13 residual stream of Gemma-2-2B base and chat.
- **What the original model already having it means:** the base model's activations are explained (in least-squares scaling, Eq. 4) by the latent's chat direction; a latent is "new" (chat-specific) if it explains almost none of base activations compared with chat activations.
- **Kind:** operational measure (Latent Scaling ratios and thresholds) with experimental findings; the thresholds are fixed by the authors without justification in the text read.
- **What it assumes:** same architecture and tokeniser for base and fine-tuned models, a dictionary trained on activations of both, one layer, and a data mix of web and chat text.
- **Is it about the fine-tune or about the task?** About the fine-tune and the data mix: results depend on the text distribution used to fit the dictionary. Two fine-tunes with equal behaviour could get different answers (unclear: not tested; only one chat-tuning is compared).
- **Objection:** authors p.10: "a significant limitation is our inability to distinguish between truly novel latents learned during chat-tuning and existing latents that have merely shifted their activation patterns, as the crosscoder architecture does not provide a mechanism to make this distinction." Also "we focused our analysis only on small models' middle layers." (Reader's) That limitation is exactly the reuse-versus-new question, so the paper's "chat-specific" label should be read as "not explained by the base model's activations", not as "newly built".
