# Localizing RL-Induced Tool Use to a Single Crosscoder Feature

## Metadata
- **Authors**: Andrii Shportko, Shubham Bhokare, Ahmed Zeyad A Alzahrani, Bowen Cheng, Gustavo Mercier, Jessica Hullman (Northwestern University)
- **Year**: 2026
- **Source**: Mechanistic Interpretability Workshop at the 43rd International Conference on Machine Learning (ICML 2026), Seoul (workshop paper; arXiv preprint)
- **DOI/URL**: arXiv:2606.26474 (https://doi.org/10.48550/arXiv.2606.26474); code at https://github.com/Antebe/model_diffing_crosscoders; sweep weights at https://huggingface.co/collections/antebe1/qwen-toolrl-crosscoder

## Summary
The authors train 48 Dedicated Feature Crosscoders (DFC) and plain Crosscoders on paired activations of Qwen2.5-3B base and its ToolRL-RL-fine-tuned version, and ask whether the RL-specific capability (structured `<tool_call>` generation) concentrates in the A-exclusive (RL-model) partition of the dictionary. They report that reconstruction through the crosscoder improves the RL model's tool correctness, that the same reconstruction passively transfers some tool-calling to the frozen base model ("capability spillover"), and that steering a single A-exclusive feature gives a large behavioural effect. The DFC partition is shown to be a "filter" rather than a clean "sink" for the RL-specific signal.

## Key Findings
- Across the 48-variant sweep, every variant improves the RL model's tool correctness after crosscoder reconstruction (mean +31.1 +/- 9.7 pp, 48/48 runs). Training MSE correlates only weakly with this gain (r = +0.08, CI [-0.21, +0.36]).
- The frozen base model gains +6.8 +/- 5.0 pp tool correctness through the same reconstruction pipeline, with no fine-tuning ("capability spillover"). Format accuracy never spills over (0 pp in all runs): the authors read this as the surface-form `<tool_call>` template staying in RL-specific features while semantic tool choice leaks into shared directions.
- Penalising the exclusive partition (lambda_excl = 1e-3) lowers RL-model fidelity relative to lambda_excl = 0 (34.8 to 25.8 pp at 5% share; 35.2 to 32.0 pp at 10%), which the authors interpret as the exclusive partition filtering rather than isolating RL-specific content.
- Steering a single A-exclusive decoder direction (feature 136 at layer 13, |S| = 1, alpha = 32) gives +65.0 pp tool correctness (95% CI [+47.9, +82.1]), matching steering of all 7 A-exclusive features. A matched CrossCoder needs |S| = 33 to reach its peak (+70 pp). Under the authors' tests the unbudgeted ceilings do not differ (p = 0.51).
- The DFC geometry (UMAP of decoder directions) separates A-exclusive, B-exclusive and shared features, while a mass-ratio-matched proxy partition of an unconstrained CrossCoder does not (HDBSCAN ARI 0.08 vs 0.93), so the separation is attributed to the partition mask rather than to label imbalance.
- The most discriminative A-exclusive features are described by autointerp as structural-template detectors (e.g., `<tool_call>` syntax, dialogue-turn structure) rather than broad tool-use concepts.

## Methodology
- Models: base Qwen2.5-3B (Model B) and ToolRL-Qwen2.5-3B (Model A, RL-fine-tuned with execution-feedback reward). Crosscoders trained on 40k FineWeb and 40k ToolRL samples for 9,000 steps (Adam, lr 1e-4).
- Sweep: 5 axes (architecture CC vs DFC, dictionary size 8,192 / 16,384, top-k 45/90/160, exclusive share 3/5/10%, exclusive L1 0 or 1e-3), 36 DFC and 12 CC variants.
- Behavioural scoring: format accuracy, tool correctness (fuzzy name match), and an overall score in {-1, 0, +1, +2}; 100 held-out ToolRL prompts per variant, greedy decoding.
- Feature selection: features ranked by Cohen's d on tool vs general-text activations, filtered by firing rate. Steering adds alpha times the decoder column to the residual stream at layer 13 (plus a cross-layer sweep). Evaluated on 40 prompts per cell.
- Geometry: UMAP + HDBSCAN on decoder directions, with a mass-ratio proxy partition for the CrossCoder. Autointerp uses an LLM explainer and detection scoring on top-activating examples.

## Relevance to Proposal
**Score: 4**

This paper is a model-diffing study of an RL fine-tune using crosscoders, not a parameter decomposition, so it does not test the proposed map Phi(D, delta W) or the commuting step. It is relevant to strand 2 (feature-level model diffing base vs fine-tuned, feature transfer to the base model) and strand 4 (what RL adds mechanistically, and whether RL-specific features are localised or delocalised), and it gives a concrete empirical hint that joint decompositions can leak fine-tuning-specific signal into the shared dictionary, which bears directly on whether a decomposition of W can carry a post-training update.

## Limitations
- Authors' own: a single model pair (Qwen2.5-3B) and a single task (ToolRL); the architecture effect rests on 12 CC vs 36 DFC runs and is not significant (p = 0.12).
- Authors' own: steering best-cell numbers come from n = 40 prompts per cell and have not been replicated on a fresh sample.
- Authors' own: "capability" means propensity to emit correct tool calls under one fixed prompt; no prompted base-model baseline was run, so "installs a capability" is not established.
- Apparent: the headline steering and sweep numbers are maxima over alpha and cells evaluated on the same prompts, which is optimistically biased; no held-out selection is reported.
- Apparent: the spillover claim is an activation-reconstruction effect; the crosscoder is trained on the RL model's activations as well, so it is not clear how much of the base model's gain reflects the RL-specific signal being injected rather than a capability the base model already has. The 48/48 sign test and paired t-tests treat variants that share prompts and training data as independent.
- Apparent: the B-exclusive zero-effect result is a harness sanity check, not a baseline. Cohen's d values above ~5 are driven by near-zero variance, as the authors note.
- Apparent: autointerp covers only A-exclusive features, and the shared partition, which the authors say carries most of the spilled signal, is not interpreted.
- No parameter decomposition (VPD/SPD/APD) is used; no stability, identifiability or cross-run matching analysis is reported.
